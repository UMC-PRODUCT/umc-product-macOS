# 먹물 우체부의 접지부두

- 작성일: 2026-11-25
- 작성자: 제옹(euijjang97)
- 대상: UMC Desk 홈 아케이드 · Mac · 1인칭 3D 웨이브 액션
- 상태: 첫 구역 설계 원본. 구현 빌드, 플레이 영상, 성능 실측은 후속 구현에서 채운다.

종이배의 마지막 우편물이 부두에 묶였다. 플레이어는 우체부의 커다란 인장으로 접힌 종이 정령을 펴고, 부두 한복판의 소인기를 깨운다. 한 판을 마친 사람이 **어느 길로 피했고, 고른 인장이 다음 파동을 어떻게 바꿨는지** 이야기할 수 있어야 한다.

## 첫 구역의 평면과 시야

남쪽 접수대에서 북쪽의 둥근 소인기를 바라보고 시작한다. 아래 칸은 거리 비율 대신 길의 연결을 표시한다. 바깥 물결과 난간은 경계이고, 모든 실선 길은 양방향이다.

```text
                         북
                 [원형 소인기 / 보스]
                    │           │
             [줄무늬 아치]──[종루 / 삼각 지붕]
                    │           │
 [서쪽 봉투문]──[두루마리 광장]──[동쪽 우표문]
                    │           │
                [남쪽 접수대]──[접힌 다리]
                         시작 ↑
```

- 접수대에서 중앙의 낮은 두루마리 너머로 소인기 윗부분이 보인다. 바닥의 굵은 우편 점선은 광장까지 이어진다. 서쪽은 세로 줄무늬, 동쪽은 톱니 테두리여서 회색 화면에서도 돌아갈 길을 찾을 수 있다.
- 첫 파동에서는 광장과 남쪽 순환로를 쓴다. 북쪽 두 입구에는 접힌 종이띠를 건다. 능력을 고르면 종이띠가 펼쳐져 북쪽 순환로가 열린다. 중앙 두루마리는 시선을 가리되 양옆 통로에 각각 한 번의 이동 여유를 둔다.
- 진입문 위 종이 깃발이 먼저 펴지고 문턱의 바닥 무늬가 차오른 뒤 정령이 등장한다. 플레이어 바로 뒤나 발밑에는 소환하지 않는다. 해당 문을 등지고 있으면 화면 가장자리의 문 모양과 방향 자막으로 예고한다.
- 낙하 즉사나 점프가 필요한 지름길은 두지 않는다. 회색 상자로 만든 첫 버전부터 양방향으로 한 바퀴씩 돌며 난간·두루마리 모서리에 걸리는지, 어느 교차점에서도 다음 표지가 하나 이상 보이는지 확인한다.

## 판의 순서와 인장 규칙

아래 횟수·시간·점수는 **첫 플레이 테스트용 제안값**이다. 처음 한 판은 약 3분을 목표로 하며, 대기·선택·일시 정지 중에는 제한 시간이 흐르지 않는다.

1. **접수대.** 시작 버튼을 누르면 시점을 잡는다. 가까운 빈 봉투에 기본 먹방울을 한 번 찍으면 검은 점이 둥근 소인으로 퍼진다. 남쪽 접수대를 벗어나기 전에는 피해가 없다. 화면 하단에 봉인 세 칸, 중앙에 빈 원 조준점, 상단에 파동 목표를 둔다.
2. **첫 파동.** 서쪽에서 ‘접지콩’ 두 마리가 한 마리씩 튀어나온다. 몸이 네모로 접혀 한 박자 멈추면 다음 박자에 표시된 바닥 칸으로 튄다. 이어 동쪽에서 ‘풀칠연’ 한 마리가 고리 모양 종이를 띄운다. 고리의 점선이 닫히기 전에 옆으로 걸어 나올 수 있다. 접지콩에는 소인 한 번, 풀칠연에는 두 번이 필요하다. 펼친 정령 한 마리당 50점. 남은 수가 0이 되면 위험 표시와 잔여 고리를 지우고 선택대로 넘어간다.
3. **세 인장 중 하나 선택.** 광장의 두루마리가 세 칸으로 펴진다. 시뮬레이션을 멈추고 선택 전까지 세 효과의 그림과 동사를 함께 보여 준다. 방향키로 둘러보고 Return 또는 클릭으로 하나만 확정한다. 확정에 쓴 입력을 놓은 뒤 장면 입력을 다시 받는다.
4. **두 번째 파동.** 북쪽 띠가 열리고 첫 조에 접지콩 두 마리가 나란히, 풀칠연 한 마리가 뒤따른다. 두 번째 조는 동쪽 문에서 같은 구성으로 나온다. 첫 조에서 고른 능력의 고유 효과가 적어도 한 번 드러나도록 같은 출현 순서를 쓴다. 기본 인장만으로도 통과할 수 있다.
5. **보스 ‘우편종지기’.** 마지막 정령이 펴지면 종루가 세 번 울리고 목표가 ‘소인기 세 면 펼치기’로 바뀐다. 소인기가 바닥에 사선 띠를 찍으면 빈 통로로 이동한다. 띠가 잦아들면 보스의 봉투 면 하나가 펴져 둥근 표적이 드러난다. 소인을 한 번 찍으면 해당 면이 우표처럼 떨어진다. 놓치면 같은 면을 다시 연다. 둘째 면부터 띠의 방향을 바꾸며, 마지막에는 서로 다른 방향을 한 번씩 순서대로 예고한다. 안전 통로 하나를 항상 남긴다.
6. **승리와 패배.** 세 번째 면을 펼치면 종이배가 떠나고 승리 보너스 300점을 준다. 위험 무늬가 발동할 때 겹치면 봉인 한 칸이 비고 1초간 재피해를 막는다. 세 칸이 비면 패배다. 같은 시뮬레이션 틱에 마지막 면과 마지막 봉인이 소진되면 승리로 한 번만 확정한다. 결과판에는 펼친 수, 고른 인장, 보너스, 합계와 ‘다시 한 판’·‘홈으로’를 표시한다.
7. **재도전.** 새 판은 접수대에서 봉인 세 칸, 점수 0, 기본 인장, 닫힌 북문으로 시작한다. 예고·투사체·눌린 키·능력 타이머를 비운다. 승패당 기록 한 번, 중도 포기는 기록 0건이다. 결과에서 재도전과 홈 이동을 연속 입력해도 누적 점수는 한 번만 오른다.

| 인장과 카드 문구 | 다음 파동에서 체감할 차이 | 판독 단서 |
| --- | --- | --- |
| 겹우표 · ‘나란히 찍기’ | 먹방울이 좌우 두 점으로 갈라져 나란히 나온 접지콩을 한 동작으로 펼친다. 한 개체에는 동작당 소인 한 번만 적용한다. | 조준점이 쌍원으로 바뀌고 바닥에 두 점이 찍힌다. |
| 메아리인 · ‘한 박자 뒤 다시 찍기’ | 찍은 자리에 얇은 원이 남아 한 박자 뒤 같은 위치에 소인 한 번을 더 남긴다. 풀칠연이 머무는 동안 두 겹을 펼칠 수 있다. | 빈 원이 차오른 다음 짧은 두 번째 도장 소리가 난다. |
| 여백접기 · ‘내 자리 비우기’ | 이동 중 Space를 누르면 이동 방향으로 한 칸 미끄러진다. 제자리에서는 마지막 이동 방향을 쓴다. 벽 앞에서 멈추며 3초 후 다시 쓴다. | 발밑에 접힌 모서리, 재사용 가능 시 HUD에 펼쳐진 모서리를 보인다. |

## 그림, 소리, 접근성

부두의 원경·바닥 명도를 나누고 손짓·위험 예고·날인을 실제 게임 크기로 확인하는 과정은 [원화와 키포즈 제작 가이드](arcade-art-production.md)를 따른다.

부두는 누런 미색 종이, 먹색 외곽선, 회색 한 단계의 접힌 면으로 그린다. 환경 선은 얇고 정령의 실루엣은 두껍다. 경고용 주황은 다음에 발동할 위험에만 쓴다. 홈 카드는 기존 UMC 서체·표면 토큰을 따르고, 게임 안에서는 같은 봉투·우표·접힌 모서리 모양을 카드부터 결과판까지 유지한다.

| 사건 | 화면과 소리 | 소리·색·움직임을 줄였을 때 |
| --- | --- | --- |
| 소인 적중 / 빗나감 | 적중은 원이 닫히고 둔탁한 ‘톡’, 빗나가면 작은 잉크 점만 남는다. | 중심 모양과 표적 접힘으로 구분한다. |
| 위험 예고 / 피해 | 사선 띠와 삼각 느낌표가 먼저 나타나고 종이가 당겨지는 소리가 난다. 발동 순간 띠가 실선이 된다. 피해는 봉인 한 칸과 해당 방향 표시로 읽는다. | 무음에서는 방향 자막, 회색조에서는 사선 밀도와 테두리로 읽는다. 전면 섬광은 쓰지 않는다. |
| 선택 / 보스 면 개방 | 선택한 우표 모양을 HUD에 남긴다. 종루 세 박자에 맞춰 창 세 칸이 켜지고 열린 면에는 원을 그린다. | 박자는 세 칸과 자막으로 표시한다. ‘동작 줄이기’에서는 카메라 흔들림·시점 튕김·머리 흔들림을 끄고 종이 전환을 정지 그림으로 교체한다. 위험 예고 시간은 유지한다. |

음악·효과음 음량은 각각 조절한다. 위험 예고음이 음악보다 먼저 들리게 믹스하고 동일 사건이 겹치면 한 번만 울린다. 메뉴·카드·결과는 VoiceOver가 이름, 선택 상태, 결과 합계를 읽게 한다. HUD 숫자는 밝은 바닥에서도 불투명한 먹색 받침으로 분리한다. 작은 창에서는 안내문을 접어도 봉인·목표·위험 방향이 서로 겹치지 않아야 한다.

| 미술·음향 | 광장과 소인기를 기본/회색조/무음/동작 줄이기로 비교 | 최초 플레이어가 각 문과 안전 통로를 가리키고 보스의 열린 면을 알아본다. 실패한 위치·단서를 기록해 수정하고 같은 장면을 다시 본다. |

## 실행 증빙과 프레임타임 기록표

이 문서의 수치는 제안 기준이다. 코드 검토 시점의 SHA는 위에 기록했다. **실행 빌드 SHA는 실제로 Mac에서 실행한 체크아웃에서 따로 채운다.** 아래 표를 구현 PR에 복사해 판정자와 날짜를 남긴다.

| 실행·시연 항목 | 검수자가 채울 값 |
| --- | --- |
| 재현 빌드 | 미실행 · 날짜 / 검수자 / 전체 커밋 SHA(`git rev-parse HEAD`) / 작업 트리 변경 여부 / 앱 버전·빌드 번호 / Xcode·Tuist 버전 / 구성 |
| 실행 경로 | 미검증 · 저장소 루트에서 최초 `make bootstrap`, 이어 `make install`, `make generate`, `make open`. Xcode에서 UMCDesk 스킴과 My Mac 선택 후 Run. 홈 → 잠깐, 한 판? → 부두 카드 → 한 판 하기. 실제 사용 명령·계정 진입 조건·설정 차이를 기록. [빌드 안내](../../UMCDesk/MAKEFILE_GUIDE.md) |
| 무편집 플레이 영상 | 미촬영 · 홈에서 시작해 선택 전후, 보스, 결과, 즉시 재도전까지 같은 Mac 화면을 연속 녹화. 원본 링크와 장면별 시각 기입. 별도 패배 판 및 나머지 인장 시연 링크·시각 기입 |
| 시연 판정 | 미검수 · 입력 장치 / 무음·회색조·동작 줄이기 조합 / 통과·실패한 장면 / 결함 링크 |

성능은 화면 녹화를 끈 별도 실행에서 측정한다. 제안 기준 환경은 Apple M1·8 GB Mac, 전원 연결, 저전력 모드 끔, 60 Hz, 실제 렌더 표면 1920×1080 픽셀이다. 환경이 다르면 실제값과 차이를 기록하고 해당 환경에서만 판정한다. 첫 진입의 초기 로딩은 별도 구간으로 기록한다.

| 실측 항목 | 기록할 값 |
| --- | --- |
| 환경과 재현 조건 | 미측정 · 실행 SHA / Release 구성 / Mac 모델·칩·메모리 / macOS 빌드 / 전원·열 상태 / 주사율 / 창 크기(pt)·배율·렌더 픽셀 / 그래픽 옵션 / 측정 도구·버전 |
| 구간·횟수 | 미측정 · 예열 1판 후 같은 인장·경로·출현 순서로 3판. 각 판의 첫 파동, 두 번째 파동 최대 동시 등장, 보스 마지막 두 띠 구간에 시작·끝 표시. 선택·정지 시간 제외 |
| 원본과 집계 | 미측정 · Instruments의 표시 프레임 타임라인 또는 실제 표시 시각 로그 링크 / 판·구간별 프레임 수, p50·p95·p99·최댓값(ms), 33.3 ms 초과 횟수 / 최악 프레임 시각·장면 |
| 제안 합격선 | 60 Hz의 한 프레임 예산 약 16.7 ms. 각 판의 각 전투 구간에서 실제 표시 간격 p95 ≤ 17 ms, p99 ≤ 33.4 ms, 50 ms 초과 0건. 세 판 중 하나라도 벗어나면 원인·수정 SHA·재측정 원본을 남긴다. |
| 실측 판정 | 미측정 · 측정일 / 판정자 / 통과·보류 / 기준 이탈 구간과 후속 이슈 |

## 세 게임에 적용하는 기준

세 카드 모두 **홈에서 한 판 시작 → 규칙을 익힐 첫 입력 → 결과와 기록 → 다시 한 판 또는 같은 홈 카드로 복귀**까지 Mac에서 검수한다. 각 게임에는 입력 장치별 조작표, 비활성 창 복귀 시험, 색·소리 대체 단서, 회원별 기록 회귀 결과, 실행 SHA와 무편집 영상, 부하가 가장 큰 구간의 실측을 남긴다.

부두의 장르별 검수 장면은 1인칭 회전, 두 번째 파동 밀집, 세 인장의 차이, 보스의 안전 통로다. 다른 두 게임은 장르를 정할 때 각각 **첫 입력으로 무엇을 배우는가 / 성공과 실패를 무엇으로 읽는가 / 어느 장면에서 부하가 가장 큰가**를 정의하고 그 장면으로 같은 증빙표를 채운다. 예를 들어 타이밍이 핵심이면 입력과 결과가 표시되는 간격을, 정밀 배치가 핵심이면 창 크기별 위치 일치와 오입력을 본다. 두 예시는 장르 결정 이후 검수 장면을 고르는 방법이다.
