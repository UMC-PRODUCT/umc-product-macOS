# macOS 텍스트 필드

작성자: 제옹(euijjang97) · 기준일: 2026-11-28

목록에서 **찾는 입력**에는 돋보기와 검색어 지우기가 있는 캡슐을 사용한다. 이름·주소처럼 **저장할 값을 편집하는 입력**에는 둥근 사각형을 사용한다. 설정 검색의 가로 여백과 지우기 동작, 사용자가 제시한 Codex의 채팅 검색과 이름 변경 화면이 기준이다. 패널 안에서도 같은 역할은 같은 형태를 쓴다.

## 어떤 필드를 선택하는가

| 입력 | 예시 | 선택 기준 |
| --- | --- | --- |
| 검색 | 공지 제목·본문, 스레드 제목·소개, 프로젝트 탐색 | 왼쪽에 돋보기, 가운데에 입력, 오른쪽에는 입력값이 있을 때 지우기 버튼을 둔다. 검색어를 지우면 같은 필드에서 입력을 이어간다. |
| 한 줄 폼 | 이름 변경, 프로젝트 제목, 링크, 문의 제목 | 힌트나 레이블에서 입력할 값을 알 수 있게 한다. 값이 들어 있어도 읽을 수 있는 레이블 또는 접근성 이름을 제공한다. |
| 비밀번호 | 로그인과 계정 등록 | 보안 입력과 기존 표시 전환·검증·자동 완성 의미를 유지한다. |
| 여러 줄·특수 입력 | 본문, 채팅 작성 영역, 자리별 인증 코드 | 줄바꿈, 자동 전진, 길이 제한, 문자 수 안내 등 해당 에디터의 기존 동작을 우선한다. 내부의 한 줄 필드에 외곽선을 반복해 그리지 않는다. |

## 크기와 상태

| 요소 | 검색 | 한 줄 폼 |
| --- | --- | --- |
| 외곽 | 캡슐, 기본 높이 최소 36pt | 모서리 12pt, 기본 높이 최소 36pt |
| 가로 여백 | 16pt, 아이콘과 입력 사이 8pt | 12pt |
| 기본 표면 | `backgroundSurfaceGreyWeak`, 설정은 현재 테마 팔레트 | `backgroundSurfaceWhite`, 1pt 중성 테두리 |
| 포커스 | 활성 에디터에 브랜드색 테두리 한 겹 | 같은 외곽에 포커스 색을 표시 |
| 값 있음 | 검색어 지우기 표시 | 입력값, 검증 메시지, 저장 동작은 화면이 관리 |

## 구현 계약

- 공통 검색 컨테이너 `UMCSearchField`에는 현재 문자열, 포커스 여부, 지우기 동작, 실제 입력 컨트롤을 전달한다. 검색어와 결과는 Feature가 소유한다. 공지처럼 제출 후 조회하는 검색에서는 빈 문자열 제출과 입력 지우기의 차이를 기존 동작에 맞춘다.
- 일반 한 줄 입력에는 `.umcInputField()`를 사용한다. 이미 `.focused` 또는 네이티브 편집기로 포커스를 관리하는 곳은 `.umcInputField(isFocused:)`에 그 상태를 전달한다. 기존 바탕과 기본 둥근 테두리는 공통 표면과 중첩하지 않는다.
- 키보드 포커스는 배치가 움직이지 않는 한 겹의 테두리로 표시한다. 지우기와 제출은 각각 독립된 동작이다. 오류는 기존 설명과 함께 표시하고, 비활성 입력과 지우기 버튼은 조작되지 않아야 한다.
- 네이티브 입력을 감싸는 스레드·고객센터는 AppKit 편집기의 조합 문자열과 delegate를 유지한다. 조합 중인 문자를 바인딩 값으로 덮어쓰거나 Return 한 번으로 조합 확정과 제출을 함께 실행하지 않는다.
- 설정 테마의 검색색, 글자 크기 배율, 긴 텍스트, Light·Dark에서 전경·힌트 대비를 확인한다. 비밀번호와 실제 계정 정보는 캡처에 넣지 않는다.

[검색·폼 상태 컴포넌트](https://www.figma.com/design/kM8a1siXgusAVRRgyUZ15U/?node-id=1216-28752)는 기본·값 있음·포커스를 비교하는 기준이다. 실제 패널에서의 배치는 [공지](https://www.figma.com/design/kM8a1siXgusAVRRgyUZ15U/?node-id=1212-24088)와 [스레드](https://www.figma.com/design/kM8a1siXgusAVRRgyUZ15U/?node-id=980-15415)에서 확인한다. 편집 환경에서 Pretendard Variable을 불러올 수 없어 새 Figma 한글 레이어에 Noto Sans KR 14pt를 사용했다. 앱은 프로젝트의 사용자 설정 서체와 배율을 따른다.

## 적용 예외

매칭 지원서의 답변, 공고 소개, 지원 폼 설명과 고객센터의 공개 FAQ 질문·문의 작성 제목은 입력하면서 줄 수가 늘어나는 편집기다. 짧은 텍스트를 받더라도 기존 줄바꿈과 최대 높이를 유지한다. macOS 시스템 알림 안의 설정 테마 이름은 시스템이 입력 배치와 키보드 이동을 소유한다. 인증 코드처럼 자리별로 이동하는 입력은 기존 정렬과 포커스 순서를 유지한다.

## 검수 흐름

1. 공지 패널에서 ⌘F로 포커스하고 한글을 입력한다. 입력 중과 Return으로 검색한 뒤의 목록을 비교하고, 검색어를 지운 뒤 같은 필드에서 다시 입력한다.
2. 스레드·고객센터에서 한글 조합 중 Return과 방향키를 눌러 목록 이동이나 제출이 먼저 실행되지 않는지 확인한다. 조합이 끝난 뒤 기존 탐색·선택 동작을 확인한다.
3. 폼을 Tab과 Shift-Tab으로 이동한다. 각 입력에는 포커스 표시가 한 겹만 보이고, 필수값 누락과 저장 중 상태에서는 기존 제출 제약이 유지돼야 한다.
4. 설정 검색에 사용자 테마를 적용하고 최근 검색 추천으로 이동했다가 돌아온다. 키보드 포커스, 추천 위치, 글자 크기가 이전 동작과 일치하는지 확인한다.
