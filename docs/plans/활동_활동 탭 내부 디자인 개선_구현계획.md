## 공통 규칙과 활동 치수

기존 UMC Typography/Color/Spacing/Radius, 표면·상태 텍스트·SF Symbol, 네이티브 버튼/Picker,
UMCCheckboxStyle을 사용한다. 신규 전역 토큰·공통 Swift 코드는 없다. 공통 변경은 필요한
38개 한·영 문자열 추가뿐이며 기존 키의 값은 그대로인지 별도 검사한다.

816/572/400/360/64pt와 시트 최소·기본 폭은 활동 전용 치수다. `Layout`은 현재 제안 크기와
subview의 고유 크기로 배치하며 GeometryReader, State/Binding/PreferenceKey 크기 환류,
축소 배율·고정 행 높이를 쓰지 않는다. 새로운 애니메이션이 없어 Reduce Motion 별도 전환도 없다.
대비 증가 시 명단 구분선은 기존 strong border 토큰으로 바뀐다.

## 보존 경계 점검

- capabilities/canReview 재조회 전 값을 지우지 않는다. studyTools 그룹 변경은 기존처럼 nil부터 시작한다.
- 자동 선택의 선택 ID → 열린 일정 → endsAt > now → 마지막, 다가오는 목록 endsAt >= now,
  최근 status != nil 역순, 30초 Timeline 및 Data 날짜 조회 범위를 그대로 둔다.
- phase는 onTime >= now, deadline은 onTime > now. 정각에 정시 phase와 closes 남은 시간이 공존한다.
- ScheduleEditor valid는 그대로다. track일 때만 참여자·시간순서 필수, title trim과 venue 원문 count를 유지한다.
- StudyEditor valid·trim·rename 차이·assign 한 명, 프로필 operationID/pending 복구·이력 변경 초기화 그대로다.
- ActivityForm은 버튼 행만 disabled, 사유 입력은 활성이다. 전체 시트는 interactive dismissal을 잠근다.
  일정·스터디·프로필의 기존 전체 disabled는 유지한다. 위치 취소는 onDisappear이며
  AttendanceLocation의 반경50m·20초·측위나이 strict30초·정확도0...50m는 수정하지 않았다.
- 새 API·권한·위치 요청 없음. Domain/Data·인증·라우팅·공통 빌드 구조 변경 없음.

CODE_SIGNING_ALLOWED=NO, TUIST_PRERELEASE=0. 앱은 실행하지 않았다.

실창 인계 후 단일 조작 담당만 다음 fixture를 실행한다.

```sh
python3 tools/qa/activity_design_fixture.py --port 0
# 출력된 port/control을 기록. 앱은 DEBUG --local-api-port <port>로 실행.
# second@example.test / fixture-only: 운영자
```

fixture는 session_fixture의 기존 인증 진입을 상속하고 activity handler만 별도 module instance로
격리한다. 메모리 token store·loopback API를 사용하며 실계정·Keychain·운영 API는 쓰지 않는다.
출석·판정·포인트 변경은 private fixture 메모리에서만 일어난다. 서버의 현재 지원 완료 증거는 아니다.

| 재현 | control의 marker / 조작 |
| --- | --- |
| 100자 제목·50자 그룹·긴 이름·300자 사유·다일 | 기본 데이터. 운영자 출석 관리701은 EXCUSED_PENDING |
| 조회 오류·쓰기 오류 | fail-read-once / fail-write-once; 1회 소비. 재조회 후 쓰기 횟수를 로그에서 확인 |
| 검색0건·실패 | empty-search / fail-search; 제거 후 입력 변경 또는 조회 재시도 |
| 권한 조합 | no-create / no-track / no-review / no-decide; 상단 새로고침·재진입으로 반영 |

| 제출 잠금 | hold-write 생성 후 저장/사유 제출, 입력·닫기·Esc 관측 후 marker 제거 |
| 포인트 미확정 | drop-point-receipt-once → point-ledger-unavailable 자동 생성. 제거 뒤 원장 재확인 |

위치 시트 표본은 좌표를 제거해 실제 GPS 요청 자체가 불가능하다. 위치 제출 중 잠금은 코드 대조만
했고 실제 위치 검증은 하지 않는다. Map 표시와 실제 위치 권한/측위는 구별한다.
시간 정각은 GUI 실행 시각에 의존시키지 않고 ActivityTiming 단위 테스트로 검증한다.
프로세스를 다시 띄워도 기존 프로세스·control·다른 QA 창을 점유하지 않는다.
로그는 control/activity-requests.jsonl와 control/events이며 token/비밀번호/요청 본문은 기록하지 않는다.
