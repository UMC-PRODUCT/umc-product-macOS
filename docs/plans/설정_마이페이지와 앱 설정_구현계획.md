**목표:** Figma의 설정·마이페이지 20개 상태와 실제 계정 API·macOS 환경 동작을 구현한다.\
**구조:** `SettingsPresentation → SettingsDomain ← SettingsData`, 앱 composition root에서 공유 객체를 주입한다.\
**기술:** SwiftUI, Observation, 기존 Moya/Aquila, ServiceManagement, UserNotifications, CoreLocation, AppKit. 새 외부 패키지를 추가하지 않는다.\
**설계:** [설정_마이페이지와 앱 설정_설계.md](../specs/설정_마이페이지와%20앱%20설정_설계.md)

## 공통 제약

- macOS 26.0+, `@Observable`과 프로젝트 코딩 규약을 따른다.
- 서버 Response 정수는 `String` + flexible decoding, DTO는 custom Codable이다.
- `GeometryReader`와 측정값을 상태로 되돌리는 배치는 금지한다.
- 기존 색상 토큰은 최신 Figma와 일치하므로 재사용한다. SF Symbol은 코드, Figma 리소스는 PDF다.
- 새 시안 fixture는 `#if DEBUG`만 허용한다. `UMC_PRERELEASE`로 범위를 넓히지 않는다.
- 실제 로그인·공지·채팅·출석·개인 프로젝트 기능이 없는 경계를 화면과 검증 결과에 명시한다.
- 기존 미추적 `UMCDesk/.antigravitycli/`는 보존한다. 커밋·PR·이슈에 AI attribution을 넣지 않는다.

## 우선 검토할 실패 조건

1. 링크 하나를 비웠을 때 나머지 링크까지 유실되지 않아야 한다. Task 1의 전체 치환 요청 테스트로 확인한다.
2. 코드 소비 성공 후 프로필 조회만 실패하면 코드를 다시 보내지 않아야 한다. Task 2의 부분 성공 테스트로 확인한다.
3. 로그아웃 이후 느리게 도착한 응답이 이전 계정을 다시 표시하지 않아야 하며 갱신 도중 새로 발급된 refresh token을 서버 폐기에서 빠뜨리지 않아야 한다. Task 1의 transport 경합 테스트와 Task 2의 요청 세대 테스트로 확인한다.
4. 캐시 안의 심볼릭 링크가 외부 개인 파일을 가리켜도 삭제 범위를 벗어나지 않아야 한다. Task 3의 임시 디렉터리 테스트로 확인한다.
5. 로그인 항목 등록 거부·권한 변경·다중 창에서도 저장된 값과 실제 OS 상태가 어긋나지 않아야 한다. Task 3·4의 실패 상태와 통합 테스트로 확인한다.

## 창·사이드바 시안 보정

사용자가 제시한 앱 캡처에는 타이틀바 안전 영역 32pt가 셸 위에 더해졌고 앞선 확인에서 선택한 본문 1.3배가 남아 있었다. 시안과 비교할 때는 창 1440×960pt, 본문 1.0배, 같은 활동 데이터로 맞춘다. Retina 2× 이미지의 2880×1920px를 창의 논리 크기로 해석하지 않는다.

이후 사용자가 GPT 창처럼 레일을 더 줄여 달라고 요청했다. 이 요청에 따라 왼쪽 영역의 최종 기준을 52pt로 변경한다. 카드 최대 폭, 프로필 메뉴, 설정 보조 사이드바는 그대로 유지한다.

- [x] Settings 셸의 상단 안전 영역 중복을 제거하고 Figma 기준의 1차 크기를 실제 라이트 화면에서 확인했다. 네이티브 창 버튼이 접근성 트리에 남아 있는지 확인했다.
- [x] 상단 바는 60pt와 구분선 1pt, 탐색 아이콘은 16pt, 새로고침은 32pt 영역 안의 12pt 아이콘으로 맞춘다.
- [x] 최종 레일을 폭 44pt·왼쪽 여백 4pt·콘텐츠 간격 4pt로 줄인다. 위·아래·오른쪽 여백 12pt를 유지하여 콘텐츠 시작점을 `(52, 12)`로 맞춘다.
- [x] 아이콘은 16pt medium·영역 44×44pt를 유지하고 추가 간격을 없애 중심 간격을 44pt로 줄인다. 상단 공간은 40pt, 아바타는 32pt와 44pt 버튼 영역으로 맞춘다.
- [x] 별도 Settings 창에만 AppKit bridge와 `.toolbarBackgroundVisibility(.hidden, for: .windowToolbar)`를 적용해 제목 막대 배경을 숨기고 콘텐츠를 상단까지 확장한다. 창 버튼을 숨기는 toolbar visibility는 사용하지 않는다. `⌘,` 첫 열기와 닫은 뒤 재열기에서 제목 막대 배경이 되살아나지 않는지 확인한다.
- [x] 프로필 메뉴를 304pt 폭과 48pt 아바타, 18pt 이름, 14pt 부가 정보, 텍스트 행·구분선 구조로 맞춘 뒤 실제 popover와 로그아웃 항목의 접근성 노출을 확인한다.
- [x] 최종 레일의 라이트 캡처와 실제 설정 창 재열기를 확인한다. 타이틀바가 있는 NSWindow에서 주요 6개 화면의 최소·기준 크기와 Light·Dark 레이아웃 테스트를 통과한다.
