Figma `UMC Mac OS` 파일의 `Mid-fi` 페이지에 미드파이를 그릴 때 쓰는 명세입니다.
IA 문서가 화면 사이의 연결을 정했다면 이 문서는 화면 안의 모양을 정합니다.
미드파이로 레이아웃과 흐름, 문구를 확인하고 컬러는 UMC 디자인 시스템을 따릅니다.

## 1. 범위

**그리는 것** — IA 3장의 노드 가운데 화면·창·시트·상태 변형. 전체 목록은 9장의 프레임 표입니다.

**그리지 않는 것**

- IA 5장에 적힌 1차 범위 밖 기능
- IA 6장의 미정 가운데 위치조차 없는 것. 11장에 처리 방법을 적었습니다
- 하이파이 몫: 일러스트, 아이콘 세트 확정, Liquid Glass 재질,
  애니메이션, 카카오·애플·구글 로그인 버튼의 브랜드 가이드 색

**규칙 세 가지**

- 이 문서에 없는 화면, 버튼, 필드를 만들어 넣지 않습니다. 빈 곳은 `미정` 태그로 남깁니다
- 문구는 7장 문구 표에서, 데이터는 8장 샘플 데이터에서만 가져옵니다. lorem ipsum은 쓰지 않습니다
- 서버 데이터와 사용자가 작성한 개인 로컬 데이터를 구분합니다. 프로젝트 샘플은 로컬 기록이며 서버 응답으로 표시하지 않습니다

## 2. 고정 결정

아래 여섯 가지는 미드파이에 앞서 정해 두었고 그리는 중에 바꾸지 않습니다.

| # | 결정 | 내용 |
|---|---|---|
| 1 | macOS 26 네이티브 | `NavigationSplitView` 3컬럼, 툴바, 시트, 시스템 Alert. 커스텀 창 장식을 만들지 않습니다 |
| 2 | 창 하나 기준 | 메인 창 1440×900. 사이드바 240 · 목록 320 · 상세는 나머지. 프로젝트 자료 열람은 목록을 접을 수 있고 보조 패널은 320을 기준으로 검토합니다 |
| 3 | UMC 컬러 시스템 | 바탕과 글자는 Neutral, 주요 행동은 Teal 시맨틱 토큰을 씁니다. Error는 파괴적 동작과 실패에만 사용합니다. 권한 배지의 4색은 화면 밖 주석에만 둡니다 |
| 4 | 시스템 글꼴 크기 | macOS 텍스트 스타일 크기를 따르고 본문은 13pt입니다. `docs/claude/design-system.md`는 iOS 토큰(Pretendard 17pt, 반경 30, 하단 탭 바)이라 쓰지 않습니다 |
| 5 | 컴포넌트 먼저 | 6장의 공통 컴포넌트를 먼저 만들고 화면은 인스턴스로만 조립합니다 |
| 6 | 실제 문구 | 설계 문서의 문구를 그대로 씁니다. 설계에 없는 문구는 `초안`으로 표시합니다 |

## 3. 캔버스 규칙

**배치.** 맨 위 줄에 `00 토큰`과 `01 컴포넌트` 보드를 둡니다. 그 아래로 레인마다 가로 한 줄씩
놓습니다. 줄 순서는 G · N · T · P · M · Q이고 한 줄 안은 9장 프레임 표의 순서대로 왼쪽에서
오른쪽으로 갑니다. 프레임이 겹치지 않도록 기존 레인 배치를 가로·세로 1.18배로 벌립니다. 줄의 왼쪽 끝에
레인 이름을 텍스트로 붙입니다(예: `N 공지`).

**프레임.** 캔버스 최상위에는 화면 프레임과 보드 프레임만 둡니다. 화면 프레임은 `clip: true`입니다.

- 이름은 `{IA ID} {이름}`이고 변형이 있으면 ` · {변형}`을 붙입니다. 예: `N2 공지 본문 · 운영진 모드`
- 주요 창 프레임은 1440×900입니다. 점검·로그인은 1280×800을 유지합니다. 창 장식(신호등 버튼, 툴바)도 프레임 안에 그립니다
- 한 컬럼만 바뀌는 상태 변형은 그 컬럼만 그립니다. 보조 상태 프레임은 기존 검토 크기를 유지합니다
  (목록 300×748, 프로젝트 보조 패널 320×748). 실제 창 안에서는 남은 높이를 채웁니다
- 시트는 부모 화면 프레임을 복제한 위에 올려 그립니다. 시트만 따로 그리는 변형은 시트 크기로 그립니다

**주석.** 화면 안에는 실제 UI만 둡니다. 배지와 설명은 프레임 바깥 위쪽의 `note` 노드에 적습니다.

| 주석 | 모양 | 붙이는 곳 |
|---|---|---|
| 권한 배지 | 색 칩 + 라벨. 운영진 모드 주황 · 방 역할 보라 · 프로젝트 권한 파랑 · 조직 레벨·파트 초록 | 권한에 따라 보이는 프레임 |
| 단계 배지 | 검정 테두리 칩 + 로드맵 단계 숫자 | 모든 화면 프레임 |
| 미정 | 회색 점선 칩 `미정` + 무엇이 비었는지 한 줄 | 11장 대상 |
| 초안 문구 | 회색 칩 `초안` + 그 프레임에 쓴 초안 문구 목록 | 초안 문구를 쓴 프레임 |

권한 배지의 4색과 판정 근거는 IA 2장과 같습니다.

## 4. 토큰

컬러 기준은 [UMC 디자인 시스템의 `Color` 변수](https://www.figma.com/design/U3pRZp6BjQBW5aMljCBwo9/?node-id=2117-4956)입니다. 아래 `$` 이름은 화면 명세에서 쓰는 별칭입니다. Figma `Mid-fi` 페이지에는 표에 적힌 시맨틱 토큰 이름으로 로컬 변수를 만들고 색을 연결합니다. 화면에 색 값을 직접 넣지 않습니다. 다른 크기·간격 토큰도 `$` 별칭을 따릅니다. 원본 변수가 라이브러리로 연결되지 않아 색 값이 바뀌면 이 로컬 변수도 갱신해야 합니다.

### 4.1.1 라이트·다크 모드

`Mi-fi · Light`와 `Mi-fi · Dark`에 최신 IA의 같은 화면·상태를 둡니다. 두 모드는 정보 구조와 동작이 같고 색만 바뀝니다. 원본 UMC 컬러 컬렉션에는 라이트 값만 있습니다. 다크 모드는 기존 Grey·Teal 팔레트로 만든 로컬 매핑을 사용합니다. 원본 디자인 시스템은 수정하지 않습니다.

## 5. 창과 레이아웃

### 5.1 메인 창 (1440×900)

Figma 오토레이아웃 구조로 적으면 이렇습니다.

```
Window (가로, 1440×900, 안쪽 여백 12, $color-bg-sidebar)
├─ Sidebar (세로, 240, 높이 채움, $color-bg-sidebar)
│   ├─ 신호등 줄 (높이 52, 왼쪽 여백 20, 12px 원 3개)
│   ├─ 워크스페이스 표시 (높이 76, UMC · 10기 워크스페이스)
│   └─ 사이드바 항목 6개 (공지 · 활동 · 스레드 · 프로젝트 · 매칭 · 문의, 좌우 여백 8)
├─ 구분선 1
└─ Main (세로, 폭 채움, 반경 14, 경계선 1)
    ├─ Toolbar (가로, 높이 76, 좌우 여백 24)
    │   ├─ 제목 ($text-title3, 목록 컬럼 위)
    │   └─ 오른쪽 묶음: 레인별 버튼 · 검색 칸 · 운영진 모드 토글
    ├─ 구분선 1
    └─ Columns (가로, 높이 채움)
        ├─ List (세로, 320)
        ├─ 구분선 1
        └─ Detail (세로, 폭 채움)
```

- 사이드바 항목은 역할과 상관없이 여섯 개로 고정합니다. 계정·로그아웃·설정은 그리지 않습니다(11장)
- 사이드바는 Neutral 바탕 위에 행을 놓습니다. 비선택 행에는 흰 카드를 만들지 않고 선택한 행만 `macOS/Sidebar/selected`로 표시합니다
- 신호등에는 macOS 창 버튼의 빨강·노랑·초록을 사용합니다. 앱 콘텐츠용 UMC 컬러 토큰과 구분합니다
- 운영진 모드 토글은 운영진 권한이 있는 계정의 프레임에만 그립니다. 챌린저 프레임에는 없습니다
- 검색 칸(폭 180)은 메뉴바 ⌘F와 짝이고 스레드 툴바에만 둡니다. 서버 검색이 확인된 곳이 스레드뿐입니다(11장)
- 상세 컬럼을 고르지 않은 상태는 가운데에 `$text-title3` `$color-text-secondary`로
  "선택한 {대상} 없음"을 적습니다

### 5.2 프로젝트 작업 공간

P1~P3은 기본 3컬럼을 사용합니다. 목록에는 현재 프로젝트의 기능이 있고 상세에서 선택한 기능을
확인합니다. 프로젝트 선택은 목록 상단에 둡니다. PM·디자인·개발 관점은 P2 상단에서 바꾸며
권한 배지를 붙이지 않습니다. 개인 기록 표시를 제목 가까이에 둡니다.

P4는 넓은 자료 열람을 위해 목록을 접을 수 있습니다. 전체 창 1440×900에서 사이드바 240을
유지하고 남은 폭을 자료에 배분합니다. 보조 패널을 열면 그 안에서 320을 사용합니다.
패널이나 목록을 접어도 현재 프로젝트·기능 이름과 돌아가기 행동을 유지합니다.

웹 콘텐츠는 서비스 이름과 회색 본문 뼈대로 그립니다. Figma 화면은 프레임 윤곽으로 표시합니다.
서비스별 로그인·권한·열람 실패와 원문 열기 경로를 각각 그리며 실제 서비스 UI를 임의로 복제하지 않습니다.
P5는 상세 영역에서 입력 자료 선택과 편집 가능한 작업 설명을 보여 줍니다.

(사이드바 240 · 툴바 76 · 목록 320 · 상세 852). 사이드바는 `공지`가 선택된 상태입니다.
다른 프레임을 만들 때 이 골격을 복제해서 씁니다.

**G1 업데이트 알림.** `N1 공지 목록` 위에 `Alert/Prompt` 모양으로 띄웁니다. 버튼은
`[나중에]`(`Button/Secondary`)와 `[다운로드]`(`Button/Primary`)입니다. `[다운로드]`는 기본
브라우저로 나갑니다(X2). 버전 샘플은 `1.2.0`입니다.

**G4 오류 Alert · 세션 만료.** `N2 공지 본문` 위에 `Alert/Error`. 7장 초안 문구를 씁니다.
권한 없음 Alert은 문구만 다르므로 따로 그리지 않고 주석에 문구를 적습니다.

### 9.2 공지 (N)

**N1 공지 목록.** 툴바 제목 `공지`, 오른쪽에 새로고침. 목록 컬럼에 `List/NoticeRow` 5개,
필독 행이 맨 위입니다. 상세는 `선택한 공지 없음`입니다.

- 로딩은 `State/Loading`, 비어 있음은 `State/Empty`(`megaphone` · `공지가 없어요`),
  오류는 `State/Error`로 그립니다. 목록 컬럼만 그립니다

**N2 공지 본문.** 첫 공지를 선택합니다. 상세 컬럼은 세로로 여백 24를 두고 이렇게 쌓습니다.

1. 필독 배지 + 제목(`$text-title1`)
2. `{작성자} · {날짜} · 조회 {n}` (`$text-subheadline` `$color-text-secondary`)
3. 대상 줄 `대상 10기 전체` (`$text-caption`)
4. 구분선
5. 본문(`$text-body`, 줄 높이 20, 최대 폭 640)
6. 이미지 2장(가로로 나란히, 16:9 회색 박스) · 링크 1줄(`external-link` + URL)

읽음 처리는 보이는 UI가 없습니다. 열면 서버에 기록됩니다.

**N2 공지 본문 · 운영진 모드.** 운영진 계정으로 모드를 켠 상태라 N2에서 아래 세 곳이 달라집니다.

- 툴바 오른쪽 끝에 `Toolbar/ModeToggle` `On`
- 툴바에 `[작성]`(`square-pen`). ⌘N과 같은 동작입니다
- 상세 맨 위에 `Tabs/Segmented` `본문 | 읽음 통계`, `본문` 선택

**N3 읽음 통계.** 같은 화면에서 `읽음 통계` 탭을 고른 상태입니다.

1. 요약 줄: `전체 160명 · 읽음 128명 · 안 읽음 32명 · 80%` (`$text-body`, 숫자는 600)
2. 조건 줄: `Tabs/Segmented` `읽음 128 | 안 읽음 32`(안 읽음 선택) · `Field/Popup` 범위 `전체`
   (선택지 전체 · 지부 · 학교)
3. 표: 이름 · 파트 · 학교 · 지부. 2행을 다중 선택한 모습

다중 선택 뒤 할 동작은 그리지 않습니다(11장).

**N4 공지 작성 (미정).** 내용만 그립니다. 서버 요청(`CreateNoticeRequest`)의 필드가 전부입니다.

- `Field/Text` 제목 · `Field/TextArea` 본문
- 대상: `Field/Popup` 기수(`10기` · `전체 기수`) · 지부 · 학교 · 파트(다중 선택) · 공지 종류
  (`챌린저 공지` · 운영진 공지 3종)
- 체크박스 두 개: `필독` · `알림 보내기`
- 바닥: `[취소]` `[올리기]`(초안)

대상 조합에는 서버 제약이 있습니다(전체 기수 + 지부 불가, 지부와 학교 동시 지정 불가 등).
미드파이에서는 막힌 조합을 고르면 비활성으로 보이는 것만 한 군데 그립니다.

### 9.3 스레드 (T)

**T1 스레드 목록.** 툴바 제목 `스레드`, 새로고침 · 검색 칸. 목록 컬럼은 `고정됨` 구역
(모바일 QNA)과 `참여 중` 구역(나머지 셋)으로 나눕니다. 행은 `List/ThreadRow`를 쓰고

**T2 스레드 방 · MEMBER.** `10기 SwiftUI 스터디`를 선택한 상태입니다.

- 상세 위 머리 줄(높이 44): 이모지 · 방 이름 `$text-title3` · `12명` `$text-subheadline` · 오른쪽 `ellipsis`

1. `MineSending`
2. `MineFailed` + `Retryable`
3. `MineFailed` + `NotRetryable`
4. `MineFailed` + `Cooldown`

**T3 스레드 방 창.** 520×720 창에 T2와 같은 내용을 한 컬럼으로 담습니다. 툴바는 신호등 ·
이모지 · 방 이름 · 인원 · 방 메뉴입니다. 말풍선 최대 폭은 360입니다.

### 9.4 프로젝트 (P)

**P1 프로젝트 목록/시작.** 개인 프로젝트 이름과 최근 기능을 보여 줍니다. 빈 상태에서는
프로젝트 이름 입력과 `[프로젝트 만들기]`를 둡니다. 삭제는 대상과 로컬 삭제 범위를 확인합니다.

**P2 프로젝트 홈.** 프로젝트 선택 아래 기능 목록을 배치합니다. 상세 상단의 관점 선택을 바꾸면
같은 기능의 추천 확인 항목 순서가 달라집니다. PM은 미결정 정책, 디자인은 상태별 화면,
개발은 구현 근거를 먼저 봅니다. 기능이 없으면 `[기능 추가]`를 제공합니다.

**P3 기능 상세.** 이름·목적·완료 조건 아래 연결 자료, 수동 준비 항목, 확인 사항을 배치합니다.
해결된 항목에는 답을 보여 주고 연결한 원문 위치가 있으면 함께 표시합니다. 팀 전송이나 담당자 알림 상태는 그리지 않습니다.
자료가 없으면 `[자료 연결]`, 저장 실패 시 작성한 내용을 유지한 채 `[다시 저장]`을 표시합니다.

**P4 자료 열람.** 서비스·원문 주소·현재 기능과 `[원문 열기]`·`[기능으로 돌아가기]`를 유지합니다.
서비스별 웹 콘텐츠 뼈대를 그립니다. 로그인 필요·권한 없음·열람 실패는 서로 다른 상태로 그리며
원문 열기를 모두 제공합니다. 붙여넣은 발췌에는 출처·저장 시각을 표시합니다.

**P5 AI 작업 설명 초안.** 입력 선택과 편집 영역을 나눕니다. 원문 링크와 실제 발췌를 구분하고
미입력·미결정을 그대로 표시합니다. 초안은 정해진 형식으로 구성하므로 AI 생성 스피너나
기기 지원 분기를 그리지 않습니다. `[복사]` 후 복사 완료만 표시합니다.

**P6 기능·자료 연결 편집.** 기능 이름·목적·완료 조건, 자료 제목·서비스·URL·선택 발췌를 둡니다.
필수 값과 URL 오류는 입력 가까이에 표시하고 저장 실패에서는 입력을 보존합니다.
바닥에 `[취소]`·`[저장]`을 둡니다. 편집한 자료는 원문을 수정하지 않습니다.

### 9.5 매칭 (M)

**M1 매칭 목록 (미정).** 차수와 프로젝트를 어떻게 나열할지 설계에 없습니다. 두 안을 나란히 그리고
고르게 합니다. 두 안 모두 아래 요소를 공통으로 둡니다.

- 툴바: 제목 `매칭` · 새로고침 · `[프로젝트 생성]`(Plan 파트) · `[차수 개설]`(지부장 이상)

| 안 | 목록 컬럼 |

| A 차수 팝업안 | 맨 위 `Field/Popup` 차수 선택(`기획-개발자 1차 매칭`) + 아래 한 줄 `지원 9월 21일–9월 27일 · 선발 마감 10월 1일` → 구분선 → `List/ProjectRow` 3개 |

**M2 공통 머리.** 세 변형 모두 상세 맨 위에 둡니다.

- 썸네일 48 · 프로젝트 이름(`$text-title1`) · `PO 박기획 · 한빛대학교`
- 한 줄 설명(`$text-body` `$color-text-secondary`) · 외부 링크(`external-link`)
- 파트 인원: `{파트} {현재}/{정원}` + `Badge/Status`(`모집 중` Accent / `모집 완료` Neutral)

**M2-읽기 읽기 전용 상세.** 공통 머리 아래에 설명 전체와 파트 인원 표(파트 · 인원 · 모집 상태)만 둡니다.
버튼은 없습니다.

**M2-지원 지원 폼.** 챌린저 계정(김유엠)입니다. 공통 머리를 한 줄로 줄이고 그 아래에 폼을 둡니다.

- 구역마다 제목(`$text-title3`)과 설명. 공통 구역 → 내 파트 구역 순서
- 질문 유형별 컴포넌트: 단답 `Field/Text` · 장문 `Field/TextArea` · 단일 선택 `Field/Radio` ·
  다중 선택 `Field/Checkbox` · 드롭다운 `Field/Popup` · 파일 `Field/File`. 필수 질문은 제목 뒤에 `*`
- 바닥 고정 막대(높이 52, 위 구분선): 오른쪽 `[제출]`(초안) `Button/Primary`
- 일정(`SCHEDULE`)과 포트폴리오(`PORTFOLIO`) 유형은 그리지 않습니다(11장)

**M2-심사 심사 화면.** PO 계정(박기획)입니다. 상세 컬럼을 위아래로 나눕니다.

1. 공통 머리 한 줄
2. 조건 줄: `Field/Popup` 차수 · 파트 · 상태(`전체` · `대기` · `합격` · `불합격`)
3. 표(높이 220): 차수 · 파트 · 챌린저 · 상태 · 지원시각 · 처리시각. 서버 기본 정렬(차수 → 파트 →
   지원이 빠른 순)대로 두고 첫 행(김유엠)을 선택합니다
4. 선택한 지원서: 이름 · 학교 · 파트 머리, 그 아래 구역별 질문과 답(질문 `$text-headline`, 답 `$text-body`)
5. 바닥 고정 막대: 현재 상태 `Badge/Status` · 오른쪽 `[불합격]`(`Button/Destructive`) `[합격]`(`Button/Primary`)

주석에 `판정은 선발 마감(10월 1일)까지 합격↔불합격을 바꿀 수 있음`을 적습니다.

**M2-심사 · 불합격 확인.** 심사 화면 위에 `Alert/Prompt`(7장 초안 문구)를 띄웁니다.

**M2-심사 · 판정 중.** 상세 컬럼만 그립니다. `[합격]`을 누른 뒤 서버 응답을 기다리는 동안
`[합격]`은 `Loading`, `[불합격]`은 `Disabled`이고 표의 상태 칸은 아직 `대기`입니다.

**M1 차수 개설 (미정).** 내용만 그립니다. 필드는 서버 요청(`CreateProjectMatchingRoundRequest`) 그대로입니다.

- `Field/Text` 이름 · `Field/TextArea` 설명
- `Field/Popup` 매칭 종류(기획-디자인 · 기획-개발자) · 단계(1차 · 2차 · 3차) · 지부
- 날짜·시각 칸 세 개: 지원 시작 · 지원 마감 · 선발 마감
- 바닥: `[취소]` `[개설]`(초안)

**M3 프로젝트 생성과 공고·지원 폼 관리 (미정).** 서버는 한 폼이 아니라 여러 단계(초안 생성 → 정보 → 파트 정원 → 제출 → 공개)입니다.

1. 정보: 이름(100자) · 설명(200자) · 외부 링크 · 썸네일 · 로고
2. 파트 정원: 파트마다 `{파트}` + 숫자 입력 한 줄
3. 바닥: `[임시 저장]` `[제출]`(초안)

제출과 공개 권한은 서버 계약을 확인하고 미정 주석으로 구분합니다. 공고·지원 폼의 질문 편집과 저장 실패도 표시합니다.

**M4 팀 확정과 결과 공개.** 파트별 판정·인원을 검토하고 영향 범위를 확인한 뒤 확정하는 흐름입니다.
처리 중에는 중복 확정을 막고 실패하면 선택을 유지합니다. 공개 후 M2-읽기에 결과가 나타납니다.
개인 프로젝트 자료가 자동 공유되는 화살표는 그리지 않습니다.

- 머리 줄: 카테고리 `출석·활동 인정` · `Badge/Status` `진행 중` · 오른쪽 `[종료]`(운영진 프레임에서만)
- 운영진이 볼 때는 머리 아래에 작성자 줄 `김유엠 · 한빛대학교 · 모바일 프로덕트 엔지니어`
- 타임라인: 8장 대화. 메시지에 컨텍스트 메뉴 표시를 그리지 않습니다(편집·삭제 없음)
- 바닥: 첨부가 있는 `Composer`

기본은 챌린저 시점으로 그리고 운영진 시점 차이(작성자 줄, `[종료]`)는 `Q1 · 운영진`의 상세 컬럼에서 보여 줍니다.

**Q2 문의 상세 · 종료.** 상태 배지 `종료`만 표시합니다. 수동 재오픈 버튼은 두지 않습니다. 입력칸은 살아 있고 위에
도움말 `메시지를 보내면 문의가 다시 열려요`(초안)를 둡니다.

**Q3 문의 등록 (미정).** 내용만 그립니다. 제목 칸은 없습니다.

- `Field/Popup` 카테고리(8장 예시 세 개)
- `Field/TextArea` 내용(자리표시 `무엇이 궁금한가요?`(초안))
- `Field/File` 첨부(도움말 `이미지·문서, 최대 50MB`)
- 바닥: `[취소]` `[보내기]`

## 11. 미정

설계에서 위치나 모양을 정하지 않은 항목입니다. 이 문서에는 미드파이에서 어떻게 다룰지만 적었습니다.

| 대상 | 비어 있는 것 | 미드파이에서 |
|---|---|---|
| 로그아웃 · 계정 · 설정 | 메인 창 어디에 두는지 | 그리지 않음. 사이드바 아래를 비워 둠 |
| 공지 · 매칭 · 문의 검색 | 메뉴바 ⌘F가 어느 레인에서 동작하는지. 서버 검색은 스레드만 확인됨 | 스레드 툴바에만 검색 칸 |
| N4 공지 작성 · Q3 문의 등록 · M1 차수 개설 · M3 프로젝트 생성과 공고·지원 폼 관리 | 시트인지, 새 창인지, 상세 컬럼인지 | 내용만 640 폭으로 그림 |
| M1 매칭 목록 | 차수와 프로젝트를 한 목록에 두는지, 단계로 나누는지 | A · B 두 안을 그림 |
| M3 · M4 상세 배치 | 생성·폼 관리와 팀 확정 단계의 세부 배치 | PRD M3·M4 흐름으로 구성하고 서버 권한은 검증 후 반영 |
| 공지 목록의 기수·운영진 공지 구분 | 목록 상단 조건 줄의 세부 배치 | N1에 기수 선택과 공지 탭 표시 |
| 공지 투표 | 공지 상세에 투표(`vote`)가 오지만 설계에 없음 | 그리지 않음 |
| 읽음 통계 다중 선택 뒤 동작 | 서버에 안 읽은 사람에게 다시 알리는 API(`POST /notices/{id}/reminders`)가 있음. 1차에 넣을지 | 선택 모습만 그림 |
| 스레드 멤버 관리 | 인원 수 진입 뒤 시트·Popover 선택 | 멤버 목록·강퇴 확인·역할 변경을 PRD대로 표시 |
| 스레드 메시지의 답장 · 리액션 · 파일 · 멘션 | 서버에는 있지만 설계에 맥 표시 방식이 없음 | 텍스트와 시스템 메시지만 그림 |
| 강퇴돼 방이 닫힐 때 | 안내 문구를 띄우는지 | 그리지 않음 |
| 점검 화면 해제 | 점검이 끝났는지 다시 확인하는 방법(버튼, 주기 조회) | 버튼 없이 그림 |
| 부분 점검 · 예정 점검 | 서버는 `PER_DOMAIN` 부분 점검과 `upcoming` 예정 점검도 줌. 설계는 전체 덮기만 적음 | 그리지 않음 |
| 불합격 사유 | 서버 판정 요청에 선택 입력 `reason`(500자)이 있음. 받을지 | 확인 다이얼로그에 입력칸 없이 그림 |
| 지원 폼 일정·포트폴리오 문항 | `SCHEDULE`·`PORTFOLIO` 유형의 입력 모양 | 그리지 않음 |
| 지원 폼 임시 저장 | 서버에 임시 저장 상태(`DRAFT`)가 있음. 맥에서 쓸지 | 그리지 않음 |
| 운영진 문의 표의 자리 | 표를 어느 컬럼에 둘지 | 목록 컬럼을 480으로 넓혀 그림(미드파이 제안) |
| 문의 재오픈 | 새 메시지로 자동 재오픈 | 수동 버튼 없이 입력 도움말 표시 |

## 12. 그리지 않을 것

- IA 5장의 제외 범위: 리크루팅, 원격 푸시, 공지 AI 초안, 스레드 자동 분류,
  프로젝트 팀 공유·자동 변경 감시·AI 누락 점검·토큰 관리, 문의 편집·삭제·수동 재오픈

- 하이파이 몫: 일러스트, 아이콘 세트 확정, Liquid Glass 재질, 애니메이션
- 메뉴바: 단축키는 버튼 툴팁이나 주석으로만 적고 메뉴바 자체는 그리지 않습니다
- 외부 서비스의 실제 모양: 자료 열람은 서비스별 뼈대만 그립니다

## 13. 작업 순서와 완료 기준

**순서**

1. 4장 토큰을 변수로 만들고 `00 토큰` 보드에 색 칩과 글자 크기 견본을 놓습니다
2. 6장 컴포넌트를 `01 컴포넌트` 보드에 만듭니다
3. `G4 메인 창 · 골격`을 만들고 복제해서 레인 프레임을 시작합니다
4. 로드맵 순서로 그립니다: N → T → P → M → Q → G의 나머지
5. 프레임마다 3장 주석(권한 · 단계 · 미정 · 초안)을 붙입니다
6. 레인 하나를 끝낼 때마다 스크린샷으로 겹침과 잘림을 확인합니다

**완료 기준**

- 9.0 프레임 표의 프레임이 모두 있고 이름이 표와 같습니다
- 화면 안의 모든 텍스트가 7장 문구 표나 8장 샘플 데이터에서 왔습니다
- 화면 안에 변수 밖의 색·크기·반경이 없습니다
- 화면은 컴포넌트 인스턴스로 조립돼 있고 복사해 붙인 원본 도형이 없습니다
- 11장의 미정 항목이 해당 프레임 주석에 모두 적혀 있습니다
