# 매칭 노치 진행 현황

작성일: 2026-11-16  
작성자: 제옹(euijjang97)  
범위: 기존 서버 정보의 macOS 노치·메뉴바 표현과 Figma 프로토타입. 앱 구현·배포는 포함하지 않는다.

## 표시와 갱신 기준

사용자는 다른 작업을 하면서 현재 차수와 내 지원 상태를 확인하고, 펼쳐서 상세 내용을 읽거나 기존 내 지원 화면으로 이동한다. 일정 단계와 개인 지원 결과를 분리한다. 서버 권한·기간·결과 공개 규칙은 변경하지 않는다.

| 정보 | 확인한 계약 | 화면 반영 |
|---|---|---|
| 차수·일정 | 차수 응답의 type, phase, startsAt, endsAt, decisionDeadline, resultPublishAt | 확인한 일정에서 현재 구간을 계산한다. 21:42·22:00 공개 예시는 ‘발표 대기’, 남은 시간 18분으로 표현한다. 임의의 마감 임박 임계값은 없다. |
| 내 지원 | `GET /api/v1/projects/me/applications` | 프로젝트·파트·차수와 본인에게 공개된 상태를 표시한다. 공개 전 null을 합격·불합격으로 변환하지 않는다. |
| 결과 | 본인 조회에서 발표 전 제출 이후 상태를 null로 가림. 기존 resultPublishAt 없는 차수는 decisionDeadline 이후 반환하는 예외 존재 | 새 응답에서 실제 상태를 확인한 뒤 결과를 표시한다. 일정 경과나 자동 처리 완료 시각만으로 공개를 선언하지 않는다. |
| 최신성 | 조회 성공 시각은 클라이언트가 기록 | ‘방금 확인’은 성공한 조회 뒤에만 표시한다. 연결 실패·수면 복귀 중에는 마지막 확인 시각과 과거 상태를 분리하고 새 결과나 카운트다운을 최신으로 단정하지 않는다. |

조회한 프로젝트 REST·GraphQL 컨트롤러와 결과 발표 서비스에서는 매칭 변경을 구독하는 SSE/WebSocket 계약을 확인하지 못했다. 기존 조회 API를 자동 갱신하는 경험으로 설계했으며, 서버가 변경 즉시 전송한다고 보장하지 않는다. 갱신 간격·재시도·절전·시계 오차 보정은 구현 시 기술 검증 대상이고, 이번에 고정 주기를 만들지 않았다. 서버 시각 전용 필드도 확인하지 못했으므로 카운트다운은 확인한 일정과 기기 시각의 차이를 사용하되 상태 판정과 분리해야 한다.

서버 main은 조회 시 `60fdadd2cb0ef7c8a252cc1903859af56ba7b015`로 동일했다. 실제 운영 배포와 응답은 확인하지 않았다.

## macOS 표현과 검증 한계

카메라 하우징에는 콘텐츠를 놓지 않고 양옆 안전 공간에 축약 정보를 배치한다. 클릭하면 아래쪽 패널을 펼치고, 닫기 또는 Esc로 축약한다. 내 지원 보기 버튼은 기존 내 지원 화면으로 연결한다. 노치가 없는 디스플레이는 메뉴바 패널로 표현한다. 검은 패널은 Light·Dark 데스크톱 모두 UMC Dark 변수를 사용해 대비를 유지한다.

Apple은 [safeAreaInsets](https://developer.apple.com/documentation/appkit/nsscreen/safeareainsets), [노치 왼쪽 영역](https://developer.apple.com/documentation/AppKit/NSScreen/auxiliaryTopLeftArea-uglc), [오른쪽 영역](https://developer.apple.com/documentation/appkit/nsscreen/auxiliarytoprightarea)을 제공한다. [NSPanel](https://developer.apple.com/documentation/appkit/nspanel)과 [MenuBarExtra](https://developer.apple.com/documentation/swiftui/menubarextra)는 구현 후보이다. 이를 조합한 노치 주변 패널은 설계 추론이며, macOS 공식 Dynamic Island API가 있다는 뜻이 아니다.

실제 기기별 노치 크기, 메뉴바 다른 항목과의 충돌, 전체 화면·Spaces·다중 디스플레이, 입력 포커스, 잠금 화면에서 개인 정보 표시 여부는 구현 전에 검증해야 한다. Figma의 196×32 카메라 영역은 배치 예시이고 하드코딩 규격이 아니다. 잠금 화면 노출 정책·백그라운드 상주·푸시 권한은 이번에 추가하지 않았다.

프로토타입은 축약→확장, 닫기/Esc→축약, 내 지원 보기→기존 내 지원 화면으로 연결했다. 오프라인·결과 상태는 응답 상황별 시안이며 시간만으로 자동 전환시키지 않았다. 메뉴바 대체 상태의 닫기는 현재 공통 축약 예시로 연결되어 있어 실제 메뉴바 팝오버의 닫힘 동작까지 재현하지 않는다.

158개 텍스트의 부모 영역 넘침·truncation을 검사했고 발견된 항목은 없었다. 카메라 예시 영역과 오른쪽 문구 사이를 6pt 이상 띄웠다. 확장 Light·Dark와 메뉴바 대체의 캡처를 직접 확인했다. 일부 Figma 캡처에서 텍스트가 누락되어 재발급했으며 최종 캡처는 `/tmp/upms-notch-final-light-v2.png`, `/tmp/upms-notch-final-dark.png`다. 실제 네트워크 갱신·실시간성·키보드 접근성·상주 창 동작은 아직 구현하지 않았다.

### Hi-fi 시각적 진행 표현 — 2026-11-17

Hi-fi의 기존 노치 10개 상태를 수정했다. 접힘에는 지원서·판정·현재 단계 아이콘과 연결선, 다음 예정 시각을 배치했다. 펼침은 600×343에서 520×254로 줄이고 현재 상태, 단계 경로, 프로젝트, 조회 최신성, 내 지원 바로가기를 남겼다. 긴 기술 설명은 이 문서에서 관리한다. 공통 진행 경로는 접힘·펼침 × 발표 대기·연결 끊김·결과 확인의 6개 컴포넌트로 재사용한다.

- 지원→판정→발표 경로는 차수 일정의 순서다. 판정 아이콘은 개인 심사 완료를 뜻하지 않으며, 임의 진행률·퍼센트·예측 소요 시간은 표시하지 않는다.
- 발표 대기는 `22:00 예정`, 실제 결과 예시는 새 응답 확인 후 `합격`으로 구분한다. 결과 예시 시계는 22:01이다. 연결 실패는 마지막 확인 시각과 확인 중단을 표시한다.
- 기존 닫기·Esc·내 지원 화면 이동 연결을 유지했다. 카메라 중앙 예시 영역은 비워두고 좌우에 축약 정보를 배치한다. Light·Dark 데스크톱 모두 검은 패널의 UMC Dark 모드를 유지한다.

10개 상태의 텍스트 158개를 검사해 부모 경계 넘침 0건을 확인했다. 아이콘과 연결선 중심을 정렬하고 확장 Light·Dark, 실제 결과, 오프라인의 렌더를 직접 확인했다.
