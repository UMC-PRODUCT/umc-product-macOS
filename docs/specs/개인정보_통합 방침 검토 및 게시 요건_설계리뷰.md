# 통합 개인정보 처리방침 검토 및 게시 요건

작성일·근거 확인일: 2026-10-10
작성자: 제옹(euijjang97)
검토 대상: 「개인정보_통합 개인정보 처리방침_설계.md」 개정안 v1.0
관리 방식: 별도 Markdown 문서. 사용자가 필요한 위치로 옮겨 관리하며 PR 생성은 진행하지 않음.
상태: 내부 확정용. 게시 승인·법률 검토 완료·서비스 수정 완료를 뜻하지 않음.

통합 방침의 운영 주체 표기는 사용자 확인에 따라 **UMC PRODUCT**로 정했다. 다만 법적 책임주체, 학교·지부 운영 조직과의 관계, 개인정보 담당부서와 연락처까지 확정된 것은 아니다. UPMS 비회원 지원과 평가·판정 이력, BackOffice 운영 정보, 앱의 기기 저장과 권한을 포함하도록 범위를 넓혔다. 확인되지 않은 기간·계약·국가·담당자 이름을 만들어 완성하지 않고 개정안의 대괄호를 B01~B13 게시 차단 항목에 연결했다.

가장 먼저 해결할 문제는 기존 고지와 구현의 차이다. **GPS 좌표가 DB에 저장되고 탈퇴 후 학교·닉네임·실명을 포함한 감사 이벤트가 생성되며 FCM 등록 해제가 실제 행 삭제로 이어지지 않는다.** 방침 문구만 바꾸어 이 차이를 해소할 수 없다. 보유 필요성·적법한 근거·기간을 검토하고 불필요한 정보와 잔존 경로를 줄인 뒤 실제 삭제와 실패 처리를 검증해야 한다. 기존에 수집·보관한 정보의 적법성도 새 방침 공지와 별도로 판단한다.

## 1. 확인한 사실과 아직 확인하지 못한 운영 현황

서버는 main `f74b9bbd7f6af65df9d797206482c71d4d27dacf`, 웹은 develop `51b03fb54b2a72e4bf4cbc84730e827c41c7c823`, iOS는 develop `e3eccec71a219ca93db74e338f8aac41a6d90923`, Android는 develop-compose `dc3b595eb2f9787ebb3e967ab387cf9361af4196`, Mac은 로컬 HEAD `f2fe04ea2fcf47d4f19b5cd2175f3879644be34e`를 기준으로 조사했다. Handbook은 main `92ff4456816c19db44a4c64ebe5c5851882e88de` 기준이며 문서의 정보 기준일은 2026-10-04다. 특정 브랜치에 코드가 있다는 사실은 해당 기능이 운영 배포에서 활성화됐다는 증거와 구분한다.

| 확인 수준 | 이번 검토에서 뜻하는 것 | 게시 확정에 필요한 다음 증거 |
| --- | --- | --- |
| 코드 확인 | 읽은 엔티티·요청·처리 경로·설정 구조에 항목이나 기능이 존재 | 실제 배포 버전·설정, 실행 결과, 데이터 수명 확인 |
| 설계 확인 | 제공된 Figma에 화면·권한·흐름이 명시 | 구현·배포 여부와 실제 저장·접근 정책 확인 |
| 기존 방침의 설명 | 사용자가 제공한 2026-02-20 시행 방침에 기재 | 당시·현재 실제 처리와 비교, 개정 이력 확인 |
| 운영 미확인 | 계약, 실제 DB·파일·백업, 설정 값, 담당부서 승인 등 | 담당자의 근거 자료와 승인 기록 |

운영 DB나 실제 지원서·평가 내용, 이용자 개인정보, 비밀키, 비공개 환경변수 값은 열지 않았다. 프로덕션 네트워크의 쿠키·SDK 전송, 백업 복구, 전 플랫폼의 탈퇴 실행도 검증하지 않았다. 따라서 삭제 완료, 해외 이전 없음, 분석 미사용 또는 출시 기능을 단정하는 근거로 이 문서를 사용해서는 안 된다.

현행 법령은 2026-09-11 시행본을 기준으로 읽었다. 2027-03-09 시행 예정 개정본은 현재 의무와 섞지 않았다. 개인정보보호위원회의 「개인정보 처리방침 작성지침(2026.4. 개정)」에 따라 실제 처리 항목·근거·기간, 위탁·이전과 권리행사 경로를 구체화한다. 방침 공개와 적법한 처리근거·별도 동의 확보는 다른 작업이다. ([현행 개인정보 보호법 제30조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1029332503), [2026 작성지침](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS217&mCode=I030010000&nttId=12018), [작성지침 PDF](https://pipc.go.kr/np/cmm/fms/FileDown.do?atchFileId=FILE_000000000560753&fileSn=1&fileExtsn=pdf))

| 제명정보 1년 보유 | 일률 1년의 법적 의무·운영 근거를 확인하지 못함 | 필요성·최소 항목·기간 산정과 개별 처리근거 승인 후 반영 |

| Firebase만 위탁 | S3·메일 발송 구현과 웹 GA4 조건부 코드도 있음 | 실제 계약 기준의 위탁표와 국외이전표 각각 마련 |
| 사진·위치·알림만 권한 고지 | iOS 캘린더·카메라·근거리, Android 카메라·근처 기기 선언 누락 | 실제 제공 기능·OS별 접근과 기기 내 처리/서버 전송 확인 |

| 책임자·연락처 자리표시자 | 실제 문의·권리행사가 불가능 | 담당부서 명칭과 실제 연락처 확정을 게시 차단 항목으로 지정 |

([지원 입력](https://github.com/UMC-PRODUCT/umc-product-web-v2/blob/51b03fb54b2a72e4bf4cbc84730e827c41c7c823/src/features/recruiting/ui/apply/ApplicantInfoFields.tsx#L14), [동적 답변](https://github.com/UMC-PRODUCT/umc-product-web-v2/blob/51b03fb54b2a72e4bf4cbc84730e827c41c7c823/src/features/recruiting/model/applyPayload.ts#L71), [비회원 동의 화면](https://github.com/UMC-PRODUCT/umc-product-web-v2/blob/51b03fb54b2a72e4bf4cbc84730e827c41c7c823/src/features/recruiting/ui/apply/AnonymousPrivacyConsent.tsx#L33))

### 우선 시정해야 할 구현과 검증 기준

**GPS는 즉시파기 약속을 지킬 수 있는 구조인지부터 결정한다.** 출석 서비스가 좌표를 Point로 저장하고 반환하며 스키마에도 위치 컬럼이 있다. 출석 결과만 필요하다면 원시 좌표의 수집·저장을 줄이는 방안을 검토하고 좌표가 꼭 필요한 경우에는 목적·기간·접근 범위를 별도로 정한다. 어느 쪽이든 신규·기존 좌표, 파일·로그·백업까지 포함해 검증한다. ([좌표 컬럼](https://github.com/UMC-PRODUCT/umc-product-server/blob/f74b9bbd7f6af65df9d797206482c71d4d27dacf/src/main/java/com/umc/product/schedule/domain/ScheduleParticipantAttendance.java#L29-L49), [좌표 저장 경로](https://github.com/UMC-PRODUCT/umc-product-server/blob/f74b9bbd7f6af65df9d797206482c71d4d27dacf/src/main/java/com/umc/product/schedule/application/service/command/ScheduleParticipantCommandService.java#L70-L85))

개인위치정보 이용에 해당하면 사업자 지위·예외·등록/신고, 위치 이용약관·동의, 원시 좌표와 이용·제공사실 확인자료를 법률 담당과 확인한다. 확인자료의 기간을 관행적으로 복사하지 않았다. OS 위치 허용은 별도 동의를 대신하지 않는다. ([위치정보법 제19조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1029559333), [제16조 포함 법령](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=277359), [공식 위치정보지원센터](https://www.lbsc.kr/))

**탈퇴 처리 기록은 회원 본인의 개인정보 잔존 문제다.** 삭제 처리 뒤 학교·닉네임·실명이 포함된 WITHDRAW 감사 이벤트를 생성한다. 계정 삭제 호출이 있다는 사실만으로 지원·평가·파일·토큰·좌표·동의 이력까지 파기됐다고 안내하지 않는다. 감사 목적과 필드의 필요성을 판단하고 불필요한 이름·소속 스냅샷을 줄이며 필요한 증빙은 근거·기간·접근 제한을 정한다. 삭제 실패와 외부 OAuth 해제 실패도 완료 응답·재처리 절차와 맞춘다. ([탈퇴 서비스·감사 이벤트](https://github.com/UMC-PRODUCT/umc-product-server/blob/f74b9bbd7f6af65df9d797206482c71d4d27dacf/src/main/java/com/umc/product/member/application/service/MemberService.java#L159-L195), [OAuth 해제](https://github.com/UMC-PRODUCT/umc-product-server/blob/f74b9bbd7f6af65df9d797206482c71d4d27dacf/src/main/java/com/umc/product/authentication/application/service/OAuthAuthenticationService.java#L260-L305))

([FCM 항목](https://github.com/UMC-PRODUCT/umc-product-server/blob/f74b9bbd7f6af65df9d797206482c71d4d27dacf/src/main/java/com/umc/product/notification/domain/FcmToken.java#L28-L53), [unregister](https://github.com/UMC-PRODUCT/umc-product-server/blob/f74b9bbd7f6af65df9d797206482c71d4d27dacf/src/main/java/com/umc/product/notification/application/service/FcmService.java#L45-L53), [탈퇴 FK 변경](https://github.com/UMC-PRODUCT/umc-product-server/blob/f74b9bbd7f6af65df9d797206482c71d4d27dacf/src/main/resources/db/migration/V2026.03.05.06.30__fcm_token_member_id_delete_fk.sql#L7-L20))

서버 감사 저장은 커밋 후 비동기이고 저장 예외를 로그 처리하는 경로다. 따라서 안전성 조치에 감사기록 무손실 보장을 쓰지 않았다. OAuth 표준·TLS·Keychain의 존재도 서비스 전체의 저장·파기 안전성을 보증하지 않는다. 실제 권한 회수·다운로드 통제·로그 점검·백업 삭제를 확인한 범위만 공개해야 한다. ## 8. 확정·시정·동의 준비를 마친 뒤 전 플랫폼에 게시한다

먼저 B01의 책임·연락처와 B02의 실제 서비스 목록을 정한다. 각 목적 DRI가 D01~D12 항목·근거·기간을 결정하고 서버·인프라·플랫폼 담당이 저장소·수탁·이전·삭제 증거와 맞춘다. 유지할 수 없는 보관·권한·추적은 필요한 구현 수정을 먼저 진행한다. 조사로 확인한 불일치를 단순히 새로운 방침 문구로 합법화하지 않는다.

그 다음 수집·이용, 필요한 제3자 제공·국외이전·민감정보·위치 동의와 선택권을 별도 준비한다. 비회원 지원의 방침 체크박스도 이 고지와 대조하고 약관·동의 증빙 버전 및 철회 경로를 맞춘다. 권리행사는 본인·대리인 확인, 접수·처리·결과 통지·제한 사유 안내까지 실제로 운영할 수 있어야 한다. 평가자료라는 이유로 일괄 비공개하지 않으며 다른 사람의 권리와 법정 제한을 건별로 판단한다. ([열람 제35조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0035&lsiSeq=283839&urlMode=lsScJoRltInfoR), [정정·삭제 제36조](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335317), [정지·철회 제37조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335441))

자동 평가·점수·AI·완전 자동 합불은 현재 확인된 사실로 기재하지 않았다. 선발·출석·제재·권한제한의 최종 결정에 사람의 실질적 판단이 있는지 확인하고 완전히 자동화된 결정이 법상 요건에 해당하면 공개·설명·검토·거부와 예외를 각각 마련한다. 아동 정책 역시 대학생 대상이라는 설명으로 대신하지 않고 실제 가입·비회원 지원·문의 절차를 확인한다. ([자동화된 결정 제37조의2](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1029332745), [시행령의 공개·권리 절차](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1027192967), [법 제22조의2 신설 규정 확인](https://www.law.go.kr/LSW/lsInfoP.do?ancNo=19234&ancYd=20230314&ancYnChk=0&chrClsCd=010202&efGubun=Y&efYd=20240315&lsiSeq=248613&nwJoYnInfo=Y))

마지막으로 개인정보 고충처리·운영 승인과 필요한 법률 검토를 거쳐 공고·시행일을 정한다. UPMS 지원·비회원 조회, BackOffice, Mac, iOS·Android의 가입·설정·권리행사 화면과 공개 웹에 같은 확정본을 노출한다. 개정 전후와 주요 변경, 이전 방침 적용기간·링크를 함께 관리하며 필요한 재동의는 시행 전에 받는다. 승인된 실제 시행일이 정해지기 전에는 작성일 2026-10-10을 시행일로 사용하지 않는다.

배포 완료 판단은 B01~B13의 근거와 담당 확인, D01~D12의 승인, 필요한 구현·동의·권리행사 절차의 검증, 전 플랫폼 노출 확인이 끝난 시점에 한다. 이번 작업은 통합 개정안과 게시 요건을 만드는 문서 작업이다. 운영 정보 확정, 법률 전문가 최종 검토, 서비스 코드 시정·배포, 실제 공고·게시와 동료 전달은 아직 수행하지 않았다.
