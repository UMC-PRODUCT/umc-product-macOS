# 활동 · 출석과 macOS 메뉴 막대

작성일: 2026-09-27
작성자: 제옹(euijjang97)
상태: 기획·Figma 반영 / 앱 구현·현장 검증 전

## 목적과 범위

개발 중에도 출석 가능한 일정을 놓치지 않고 맥에서 위치를 확인한 뒤 출석을 요청할 수 있게 합니다.
화면 위쪽의 macOS 시스템 메뉴 막대에 진행 상태를 표시합니다. 앱 창 안의 툴바와는 별개입니다.

사이드바 순서는 공지 · 활동 · 스레드 · 프로젝트 · 매칭 · 문의입니다. 활동에는 일정, 내 출석,
권한이 있는 운영진의 출석 관리를 둡니다. PM·디자인·개발 관점은 출석 권한을 바꾸지 않습니다.

## 화면과 연결

| ID | 화면 | 주요 행동 |
|---|---|---|
| A1 | 활동 · 일정과 내 출석 | 진행 중인 일정 선택, 내 기록 확인 |
| A2 | 출석 요청 | 일정의 시간·장소 확인, 현재 위치 확인, 직접 출석 요청 |
| A2-location | 위치 확인 불가 | 재시도, 모바일 출석 안내, 사유 제출 |
| A2-outside | 출석 범위 밖 | 현재 거리 확인, 위치 재확인, 사유 제출 |
| A2-online | 비대면 출석 | 위치 확인 없이 일정 정책에 따른 직접 요청 |
| A2-pending | 운영진 승인 대기 | 요청 상태와 사유 확인 |
| A2-done | 출석 결과 | 서버가 반환한 출석·지각·결석 상태 확인 |
| A3 | 출석 사유 제출 | 사유 입력, 제출, 승인 대기 확인 |
| A4 | 운영진 출석 관리 | 참가자·상태 조회, 허용된 요청 승인·거절 |
| A5 | 메뉴 막대 출석 패널 | 상태 확인, 일정 선택, A2 열기, 활동 화면 열기 |
| A5-stale | 메뉴 막대 확인 필요 | 마지막 확인 시각, 다시 확인, 로그인·점검 안내 |
| A5-multiple | 여러 일정 진행 중 | 일정별 상태·남은 시간 확인 후 선택 |

A1에서 A2를 열고 A2의 위치 확인이 어려우면 A3으로 이동합니다. 요청 응답에 따라
A2-pending 또는 A2-done을 표시합니다. A5에서 선택한 일정 ID를 전달해 같은 A2를 엽니다.
A4는 서버에서 허용한 일정과 행동만 노출합니다. 메뉴 막대만으로 권한 검사를 우회하지 않습니다.

## 위치 확인과 출석 요청

1. 서버에서 대상 일정, 참여 여부, 출석 시간과 내 요청 상태를 다시 확인합니다.
2. 대면 일정은 위치 권한을 확인하고 현재 위치를 측정합니다.
3. 측정 시각·수평 정확도·행사장까지의 거리를 검사합니다. 오래되거나 부정확한 위치로 출석을 허용하지 않습니다.
4. 인증 범위 안임을 확인한 뒤 출석 요청 버튼을 활성화합니다. 사용자가 눌러야 요청합니다.
5. 요청 중에는 중복 입력을 막고 서버 응답으로 상태를 갱신합니다. 구역 진입만으로 자동 출석 처리하지 않습니다.

현재 확인한 모바일 출석 반경 상수는 50m입니다. 맥만 반경을 넓히지 않습니다. 적용 반경과 위치
유효 시간·정확도 기준은 모바일 정책 및 서버팀과 확인한 뒤 확정하고 실제 행사장에서 검증합니다.
위치 오차가 크거나 권한이 없으면 재시도·모바일 출석 안내·사유 제출을 제공합니다.
비대면 일정은 위치 권한을 요구하지 않으며 출석 가능 시간과 대상 조건을 따릅니다.

요청이 타임아웃되면 먼저 서버 기록을 조회합니다. 접수 여부를 확인하기 전에는 자동 재전송하거나
완료로 표시하지 않습니다. 모바일에서 이미 요청한 출석도 같은 서버 기록으로 반영합니다.

## 메뉴 막대 표시

| 조건 | 짧은 라벨 | 펼친 패널 |
|---|---|---|
| 진행 중인 출석 없음 | UMC 아이콘 | 진행 중인 출석 없음, 활동 열기 |
| 출석 가능 · 아직 요청 안 함 | 출석 가능 · 12분 | 일정명, 출석 인정 마감까지 남은 시간, 출석 화면 열기 |
| 지각 요청 가능 | 지각 · 05분 | 지각 처리 안내, 요청 마감까지 남은 시간 |
| 요청 전송 중 | 요청 중 | 해당 일정 요청 버튼 비활성 |
| 운영진 판정 필요 | 승인 대기 | 사유와 상태 확인 |
| 서버에서 출석 확정 | 출석 완료 | 확정 상태와 일정 확인 |
| 서버에서 지각 확정 | 지각 처리 | 확정 상태와 일정 확인 |
| 요청 가능 시간 종료 | 출석 마감 | 서버의 최종 상태 확인, 활동 열기 |
| 둘 이상 요청 가능한 일정 | 출석 2건 | 각 일정의 요청·마감 상태와 이동 버튼 |
| 오프라인·복귀 후 확인 중 | 확인 필요 | 마지막 확인 시각, 새로고침 |
| 세션 만료·로그아웃 | 로그인 필요 | 이전 계정의 일정 정보를 숨기고 로그인으로 이동 |
| 서버 점검 | 점검 중 | 점검 안내, 요청 비활성 |

시간과 건수는 화면 예시입니다. 남은 시간은 서버의 일정 시각을 기준으로 계산하며 초 단위 점멸은
사용하지 않습니다. 출석 인정 마감과 최종 요청 마감을 구분해 표시합니다. 마감이 지났다는 이유만으로
출석 결과를 결석으로 확정하지 않습니다. 완료 표시는 해당 일정의 출석 창이 끝나면 정리하고
기록은 A1에서 계속 확인합니다. 요청할 일정이 남아 있으면 완료된 일정이 대표 라벨을 차지하지 않습니다.

패널은 폭 360을 기준으로 합니다. 일정명, 상태, 마감 정보와 주요 행동 하나를 먼저 보여줍니다.
색과 함께 문구·아이콘으로 상태를 구분하고 긴 일정명은 패널 안에서 줄바꿈합니다.
대표 일정은 요청 가능한 일정 중 다음 마감이 가장 가까운 순서로 정합니다. 같은 시각이면
일정 ID로 순서를 고정합니다. 여러 일정의 출석을 한 번에 요청하지 않습니다.

## 갱신과 앱 생명주기

MenuBarExtra와 메인 창은 하나의 출석 상태 저장소를 공유합니다. 메뉴를 열 때, 앱이 활성화될 때,
잠자기에서 복귀할 때, 연결이 복구될 때, 출석 요청 후에 서버 기록을 갱신합니다. 앱 실행 중에는
60초 간격으로 진행 중인 출석을 확인하되 실패 시 재시도 간격을 늘립니다. 이는 클라이언트 설계값이며
서버 부하와 갱신 계약을 확인한 뒤 조정합니다. 다음 출석 시작·마감 시각에도 상태를 재확인합니다.

표시용 타이머는 네트워크 요청과 분리합니다. 시스템 시각 변경이나 복귀 직후에는 남은 시간을
재검증합니다. 최근 조회 실패 시 과거의 출석 가능 표시를 유지하지 않고 확인 필요로 전환합니다.

설정에서 메뉴 막대 표시를 끌 수 있습니다. 표시가 켜져 있으면 메인 창을 닫아도 앱 프로세스와
메뉴 막대 항목은 유지합니다. 앱 종료는 별도 동작으로 제공하며 종료 후에는 표시·위치 감지가
작동하지 않습니다. 로그인 시 자동 실행은 별도 선택 사항입니다. 잠자기 중 감지나 종료된 앱의
자동 실행을 출석 기능의 전제로 삼지 않습니다. 메뉴 막대가 켜져 있다는 이유로 위치를 계속 수집하지 않습니다.

## 서버 연동 근거와 확인할 사항

2026-09-27에 서버 main의 Schedule V2 코드를 확인했습니다. 다음 항목은 기존 API이며
맥 앱 구현과 실제 서버 연동이 끝났다는 뜻은 아닙니다.

| API | 용도 |
|---|---|
| GET /api/v2/schedules/me | 내 일정 조회 |
| GET /api/v2/schedules/{scheduleId} | 일정 상세 |
| POST /api/v2/schedules/{scheduleId}/attendances/request | 출석 요청 |
| POST /api/v2/schedules/{scheduleId}/attendances/excuse | 사유 제출 |
| GET /api/v2/schedules/attendance | 운영진 출석 현황 |
| GET /api/v2/schedules/{scheduleId}/attendance | 일정별 출석 현황 |
| POST /api/v2/schedules/{scheduleId}/attendances/decide | 권한이 있는 운영진의 승인·거절 |

출석 요청 DTO에는 locationVerified와 위도·경도가 있습니다. 서버가 위치 범위를 독립적으로
검증한다는 가정은 하지 않습니다. 서버와 위치 신뢰 기준을 확인하며 인증 결과를 임의로 true로
전송하지 않습니다. 출석 권한은 ATTENDANCE 리소스의 WRITE·APPROVE 판정을 따릅니다.
일정 생성 capability와 출석 승인 권한을 같은 값으로 취급하지 않습니다.

## 완료 기준

- A1–A5가 로파이·라이트·다크 시안에 있고, 메뉴 막대와 앱 화면의 상태가 일치합니다.
- 위치 권한 거부·정확도 부족·범위 밖·비대면·전송 실패·승인 대기·결과 상태를 구분합니다.
- 여러 일정, 모바일 선처리, 로그아웃, 서버 점검, 잠자기 복귀 후에 잘못된 완료 표시나 중복 요청이 없습니다.
- 서버 계약 검토와 실제 맥의 50m 반경 현장 검증을 통과한 뒤 위치 출석 기능을 출시합니다.
