# 도구 패널의 탭별 기능과 우측 상단 배치

작성일: 2026-11-28
작성자: 제옹(euijjang97)
대상: UMC Desk의 창 오른쪽 위 도구 버튼과 이 버튼으로 여는 패널

## 원본과 적용 순서

사용자는 현재 창에서 하던 일을 유지하면서 검색 조건을 바꾸거나, 그 화면에서 가능한 다음 작업을 연다. 외곽의 위치·표면은 사용자가 제공한 Codex 화면을 따른다. 내부 행동·순서·그룹의 원본은 [UMC Mac OS Mid-Fi](https://www.figma.com/design/kM8a1siXgusAVRRgyUZ15U/?node-id=78-2)와 [Hi-Fi](https://www.figma.com/design/kM8a1siXgusAVRRgyUZ15U/?node-id=605-9566)다. 같은 화면의 Hi-Fi가 있으면 이를 우선한다. 홈·설정 등 아래에 전용 패널 원본 링크가 없는 화면은 기존 앱에서 실행 가능한 작업을 기준으로 설계했다.

2026-11-28 확정한 버튼과 패널은 사용자가 직접 변경을 지시한 범위에서만 갱신한다. 공통 리디자인·동기화·리팩터링에도 이 기준을 유지한다. 아래 위임 프롬프트는 최초 구현 기록이다. 이후 변경은 [디자인 시스템 규정](../Codex/design-system.md#우측-상단-도구-버튼과-패널)을 따른다.

## 공통 패널

- 창 제목 막대의 기존 도구 버튼을 유지한다. 버튼 바로 아래, **활성 작업면의 오른쪽 위**에 패널을 정렬한다. 오른쪽·상단 여백은 각각 16pt다. 스크롤 위치, 가운데 정렬된 본문 폭, 목록의 마지막 행은 위치 계산에 영향을 주지 않는다.
- Light는 흰색, Dark는 불투명한 대응 표면을 쓴다. 얇은 중성 테두리와 가벼운 그림자, 둥근 모서리로 본문과 분리한다. 화살표·재질 블러·창 전체 딤을 제거한다. 표준 패널은 최대 300pt, 넓은 패널은 최대 390pt다. 작은 창과 확대 글자에서는 줄바꿈과 세로 스크롤로 마지막 명령까지 접근한다.
- 첫 줄에 도구 이름과 닫기를 둔다. 검색이 있으면 제목 다음에 실제 입력, 그 아래에 주 행동, 구분선과 기능 그룹을 차례로 둔다. 입력·Picker 변경 중 패널은 열린 상태를 유지한다. 시트나 상세로 가는 명령은 닫고 기존 화면을 연다. 기능이 없는 그룹과 구분선은 함께 생략한다.
- 제목 막대 버튼 재클릭·바깥 클릭·Esc·탭 이동으로 닫는다. 첫 바깥 클릭이 뒤의 파괴적 행동까지 실행하지 않게 한다. Tab/Shift-Tab, VoiceOver 레이블·선택값, Esc 뒤 트리거 포커스 복원을 지원한다. 검색 가능한 창의 ⌘F는 해당 창의 입력 하나에만 연결한다. 검색 시트 등 기존 모달의 단축키와 충돌하지 않게 한다. 패널 인스턴스와 선택 상태는 창마다 독립이다.
- 공통 코드는 `UMCTabTools.swift`의 modifier와 기존 창 트리거를 사용한다. Feature가 소유한 검색어·필터·선택 항목·권한은 기존 소유자가 계속 관리한다. 변경 호출은 기존 제출 잠금, 권한 재확인, 취소/폐기 확인을 거친다.

## 구현 위임 프롬프트

위임자는 아래 담당별 지시에 본 문서 경로, 현재 체크아웃, 담당 파일, 검수할 시안 노드와 해당 작업의 확인 결과를 붙여 전달한다. 각 담당자는 먼저 해당 행의 실제 호출부·기존 테스트·접근 제어를 읽고 진행한다. 동시에 다른 담당자가 작업 중이므로 타인의 수정은 보존한다.

1. **공통 패널 담당** — Core/UIComponents의 UMCTabTools와 기존 창 트리거·관련 테스트를 맡는다. 공통 패널 절의 배치, 바깥 클릭, Esc, 창별 포커스와 스크롤을 구현한다. 기존 modifier 시그니처의 호출 호환성을 보장하고 일반 폭·넓은 폭을 선택할 최소한의 방법을 제공한다. 실제 macOS 창에서 버튼 두 번 누르기, 검색 입력 중 Esc, 다른 창으로 전환, 본문·사이드바 클릭을 확인한다. 호출부에 필요한 사용법과 검수 결과를 전달한다.
2. **검색·활동 담당** — Notice, Activity, Community의 Presentation과 직접 관련된 테스트를 맡는다. 위 표의 원본에서 입력/주 행동/필터를 식별해 기존 상태와 연결한다. 스터디·구성원 시트와 권한 확인을 재사용한다. 전체/필터 결과 0건에서 필터를 되돌리는 사례, 검색어 입력·시트 제출·권한 회수 사례를 검증한다. 미지원 Figma 기능은 항목별로 어떤 데이터·권한·목적지가 부족한지 기록한다.
3. **매칭·프로젝트 담당** — Matching, ProjectWorkspace, MatchingProgressPanel과 관련 테스트를 맡는다. 탐색·운영·소유자 문맥은 실제 destination, 선택 프로젝트, 권한으로 판별한다. 탐색 필터와 서브페이지를 기존 상태에 바인딩하고 목록·상세·빈 결과·다른 프로젝트로 선택 전환을 검증한다. 파괴적 동작은 기존 확인 경로를 유지한다. 접근 가능한 목적지와 제외한 항목의 근거를 보고한다.
4. **홈·문의·설정 및 통합 담당** — Home, SupportView, SettingsView와 관련 테스트를 맡는다. 사용자/운영 분기와 기존 프리뷰 경계를 유지하고 작업 중 이탈·전송 불확실·권한 회수 시나리오를 확인한다. 공통 코드는 공통 패널 담당에게, 공유 번역 카탈로그의 변경은 통합 담당 한 사람에게 모은다. 영향받은 모듈 및 앱 스킴 빌드·테스트 결과와 재현 가능한 실행 상태를 기록한다.

## 완료 판정

- 일반 크기 1440×960, 작은 창 1040×720에서 Light/Dark와 확대 글자를 확인한다. 긴 이름, 필터가 많은 패널, 빈 상태를 포함해 버튼 아래 오른쪽 정렬·불투명 표면·마지막 행 접근을 비교한다. 캡처는 저장소 밖에 둔다.
- 탭별로 패널 열기 → 실제 입력·필터·명령 실행 → 본문 조회 결과나 목적지 → 복귀를 확인한다. 선택 상태가 없는 경우·있는 경우, 권한 없음·있음, 제출 중·세션 권한 회수를 해당 경로에서 확인한다.
- 공통 모듈과 권한 경로는 별도 Astra Medium 리뷰를 받는다. 결과에 구현된 노드, 원본과 다른 점과 근거, 실행한 검증 및 직접 확인하지 못한 상태를 구분해 적는다.

## 우측 상단 열기 버튼

- 32×28pt 클릭 영역에 16pt Medium SF Symbol `slider.horizontal.3`을 사용한다. 닫혀 있는 기본 상태는 배경 없는 단색 아이콘이고, hover·열림·누름 상태에는 한 겹의 중성 원형 배경으로 피드백을 준다. 키보드 탐색 시 포커스 표시가 식별되어야 한다. 비활성 상태에서는 명령을 실행하지 않는다.
- 구현 프롬프트 — 공통 UMCTabTools.swift의 ToolsTrigger와 실제 접근성 식별자를 참조하는 테스트만 소유한다. 각 탭과 좁은 매칭 현황 창이 사용하는 공통 트리거의 크기·툴바 배치를 확인한다. 공통 코드를 통해 시각 상태를 바꾸고, 기존 Enter·Space·Esc·⌘F, VoiceOver 이름과 상태값을 보존한다. AppKit 버튼의 기본 bezel과 사용자 정의 배경이 겹치지 않게 한다. 시스템 접근 권한 없이 AppKit 호스팅 시험 창에서 기본/hover/열림 및 키보드 포커스 복구를 확인하고 전후 구별이 가능한 캡처를 /tmp에 남긴다. 테스트 통과 여부와 실측 결과를 보고한다.
- 리뷰 프롬프트 — 위 기준으로 변경된 트리거와 모든 호출부를 독립 검토한다. 양 모드 대비와 포커스, 이벤트 중복, 상태 전환, 식별자 호환에 회귀가 있는지 확인하고 구체적 결함과 재현 절차를 보고한다.

## Figma 원본 동기화

Mid-Fi와 Hi-Fi의 기준은 [공통 버튼 컴포넌트](https://www.figma.com/design/kM8a1siXgusAVRRgyUZ15U/?node-id=1212-60529)와 [화면 적용 예시](https://www.figma.com/design/kM8a1siXgusAVRRgyUZ15U/?node-id=1212-23953)다. 기본은 투명, hover·열림·누름은 최대 28pt 원형과 제목 막대 label 색 10/16/22%, 키보드 포커스는 2pt 시스템 포커스 링으로 구분한다. 32×28pt 클릭 영역과 `slider.horizontal.3`을 보존하며 밝은 본문/검은 툴바 조합은 툴바 색을 따른다.

위임 프롬프트 — Figma 파일 kM8a1siXgusAVRRgyUZ15U의 위 두 페이지와 그 페이지가 참조하는 공통 버튼만 소유한다. figma-use·figma-swiftui와 시각 변경/컴포넌트 지침을 읽고 디자인 시스템 검색 후 정확한 트리거·조상·인스턴스·반응 연결을 조사한다. 원본을 재사용하고 부득이하면 재사용 가능한 상태 variants를 만들고 두 페이지의 적용 가능한 기존 버튼에 연결한다. 기존 노드의 프로토타입 클릭과 레이아웃을 보존하고 패널 열린 프레임은 선택 상태로 표현한다. 저장 후 다시 읽어 상태, 위치, 연결 수, 노드 ID, 대표 캡처를 확인하고 원본 링크와 결과를 보고한다. 타인의 변경 보존. 파일 접근이 거부되면 즉시 보고한다.
