## 1. 목적과 범위

대시보드에서 계정과 앱 설정을 찾는 경로를 정리한다. 프로필 메뉴에는 마이페이지·설정·로그아웃을 두고 대시보드 탐색 레일의 단독 설정 아이콘은 제거한다. 탐색 레일 아래의 계정 아바타를 누르면 프로필 메뉴가 열린다. 메뉴에서 마이페이지로 이동한다.

마이페이지는 내 정보와 기수별 활동·역할을 확인하는 화면이다. UMC App의 명함, 명함첩, 교환 QR, 포트폴리오·SNS 링크 편집은 macOS에 넣지 않는다. 권한 추가는 필수 기능이며 마이페이지에서 항상 찾을 수 있어야 한다. 신규 사용자가 활동 기록이 없어도 코드 등록 화면에 접근할 수 있다.

설정은 이 Mac에서 쓰는 앱의 동작을 바꾼다. 사용자 정보나 UMC 역할은 마이페이지에서 관리한다. 이번 산출물은 기획 문서와 Light·Dark Figma 화면 및 주요 흐름의 프로토타입이다. 저장소에는 앱 기능 소스가 아직 없어 실행 가능한 화면 구현은 후속 작업이다.

‘계정·로그아웃·설정’의 진입점은 기존 문서에서 미정으로 남겼다. 이 설계로 진입점을 확정한다. 기존 전 사용자 PRD·IA·미드파이 명세의 해당 미정 항목보다 이 문서를 우선한다. 다른 작업 중인 문서는 덮어쓰지 않는다.

## 2. 진입과 창 동작

| 진입 | 동작 | 복귀 |
|---|---|---|
| 탐색 레일 계정 아바타 | 아바타 오른쪽 위에 AM1 프로필 메뉴 | 바깥 클릭·Esc로 닫고 아바타로 포커스 복원 |
| 프로필 메뉴의 마이페이지 | 메뉴를 닫고 MP1 열기 | 이전 메인 화면으로 복귀 |
| 프로필 메뉴의 설정 / 앱 메뉴 / ⌘, | 단일 설정 창 열기, 이미 열려 있으면 앞으로 가져오기 | 창을 닫아 기존 메인 창으로 복귀 |
| 프로필 메뉴의 로그아웃 | LO1 확인 다이얼로그 | 취소 시 기존 화면 유지, 완료 시 기존 로그인 화면 |

프로필 메뉴 머리는 아바타·닉네임/이름·학교·현재 기수만 보여 준다. 이메일은 메뉴에 노출하지 않는다. 메뉴 항목은 ‘마이페이지’, ‘설정…’과 단축키 ‘⌘,’, 구분선, ‘로그아웃…’이다. 참고 이미지의 사용량·요금제·친구 초대는 넣지 않는다.

설정은 SwiftUI `Settings` scene을 사용한다. 별도 창은 1120×820 시안, 최소 960×680, 사이드바 224, 상세 최대 800을 기준으로 한다. 카테고리를 바꿔도 창 크기는 유지하고 본문만 스크롤한다. macOS의 설정 단축키와 창 패턴은 [Apple Settings HIG](https://developer.apple.com/design/human-interface-guidelines/settings)와 [Settings scene 안내](https://developer.apple.com/documentation/foundation/adding-a-settings-interface-to-your-app)를 따른다.

## 3. 마이페이지

MP1은 기존 1440×960 메인 창과 탐색 레일을 재사용한다. 툴바에 뒤로 가기, ‘마이페이지’, 정보 새로고침을 두고 본문은 최대 960 폭의 세로 흐름으로 배치한다.

| 영역 | 정보와 행동 |
|---|---|
| 내 정보 | 프로필 이미지, 닉네임·이름, 학교, 본인 이메일. 이름·학교·닉네임은 현재 계약상 읽기 전용 |
| 내 활동과 권한 | 서버가 반환한 기수별 활동 기록과 역할. 기수·학습 파트·담당 역할·소속 범위를 구분 |
| 권한 추가 | 항상 보이는 주요 버튼. ‘운영진에게 받은 6자리 코드를 등록하세요’ 안내 |
| 계정 지원 | 이름·학교 등 정보 정정이 필요한 경우 기존 문의 화면으로 이동 |

기수는 전역 역할 하나로 합치지 않는다. 여러 학습 파트가 있으면 모두 표시하고 운영진 담당 파트를 수강 파트로 표시하지 않는다. 조직이 없는 중앙 운영진, 학습 파트가 없는 기록도 ‘정보 없음’ 오류로 취급하지 않는다. 서버에 없는 활동 날짜·등록 일시·역할 만료일을 만들어 표시하지 않는다.

활동 기록이 없으면 ‘아직 등록된 활동이 없어요’와 권한 추가 버튼을 보여 준다. 프로필 조회에 실패하면 재시도를 제공하고 코드 추가 진입을 유지한다. 역할명이 있다는 이유만으로 운영 기능을 열지 않고 해당 화면의 서버 capability를 다시 확인한다.

## 4. 필수 권한 추가

### 4.1 코드 등록 흐름

권한 추가는 관리자가 발급한 코드를 현재 로그인 계정에 등록하는 기능이다. 사용자가 역할·학교·기수·파트를 선택해 권한을 만드는 폼은 제공하지 않는다. 앱에 코드 발급·다른 회원 권한 부여 기능도 추가하지 않는다.

1. MP1의 ‘권한 추가’를 누르면 MP2 시트를 연다. 코드 등록 대상인 본인 이름·학교를 함께 보여 준다.
2. 코드 입력칸은 하나이며 일반 텍스트 붙여넣기와 ⌘V를 지원한다. 앞뒤 공백만 제거하고 6글자일 때 등록을 활성화한다. DTO는 문자열 길이만 검증하므로 숫자 키패드·숫자 전용 필터·대문자 강제 변환은 적용하지 않는다.
3. ‘등록’을 누르면 버튼을 ‘등록 중…’으로 바꾸고 중복 제출을 막는다. 제출 중 시트의 닫기를 제한하며 앱 자체를 강제로 종료하지 않는다. 제출 전 Esc·취소는 닫기다.
4. `POST /api/v1/challenger-record/member`에 `{ "code": "입력한 코드" }`를 보내며 성공 응답은 본문이 없는 응답이다. 권한이 추가됐다는 낙관적 UI를 먼저 표시하지 않는다.
5. 성공 뒤 `GET /api/v1/member/me`와 현재 열려 있는 화면의 capability를 다시 조회한다. 이전 기수 선택을 유지하며 새 기수가 추가돼도 자동으로 활동 대상을 바꾸지 않는다.
6. 최신 정보를 받으면 MP3 성공 상태에 서버가 실제 반환한 활동·역할을 보여 준다. ‘마이페이지로 돌아가기’와 ‘다른 코드 추가’를 제공한다. 입력 코드는 지운다.

등록 요청은 성공했지만 정보 갱신에 실패하면 ‘코드는 등록됐어요. 최신 정보를 다시 불러와 주세요’와 ‘정보 새로고침’을 표시한다. 같은 코드를 자동 재전송하지 않는다. 요청 결과 자체를 알 수 없는 타임아웃에는 ‘등록 결과를 확인하지 못했어요’를 표시하고 프로필 재조회부터 한다. 프로필로도 확인되지 않으면 사용자 재시도를 제공하고 자동 재전송은 하지 않는다.

### 4.2 오류와 보호

| 서버/로컬 상태 | 표시와 복구 |
|---|---|
| 6글자 미만·초과 | 입력 도움말, 등록 비활성. 7번째 글자를 조용히 버리지 않음 |
| 존재하지 않는 코드 | 코드 확인 안내, 입력 유지 |
| CHALLENGER-0012 이미 사용한 코드 | ‘이미 사용한 코드예요. 새 코드를 받아 주세요’, 담당 운영진에게 문의 |
| CHALLENGER-0013 이름 불일치 | ‘코드의 이름이 내 정보와 일치하지 않아요’, 코드 확인 또는 정보 정정 문의 |
| CHALLENGER-0014 학교 불일치 | ‘코드의 학교가 내 소속과 일치하지 않아요’, 코드 확인 또는 정보 정정 문의 |
| CHALLENGER-0002 이미 등록된 활동·역할 | 현재 등록 정보 보기, 실패를 성공으로 바꾸지 않음 |
| 활동 상태·코드 구성 오류 | 서버 오류 사유를 안전한 안내로 표시, 운영진 문의 |
| 네트워크 실패 | 입력 유지, 사용자 재시도. 서버 반영 여부가 불확실하면 프로필 재조회 |
| 세션 만료 | 기존 재인증 흐름, 코드를 로그·디스크·복원 데이터에 저장하지 않음 |

일반 사용자는 권한 확인 없이 `GET /challenger-record/code/{code}`로 등록 전에 타인의 기록을 미리 조회하지 않는다. 이 조회 API에는 CHALLENGER_RECORD READ 검사에 따른 제한이 있다. 서버가 이름·학교와 코드 사용 여부를 검증하고 회원 단위 잠금 및 권한 캐시 삭제를 처리한다. 클라이언트는 코드가 가진 권한을 계산하지 않는다. 코드는 입력 중 메모리에만 유지하고 분석 이벤트·크래시 로그에도 넣지 않는다.

## 5. 앱 설정

왼쪽 카테고리와 오른쪽 그룹형 행으로 구성한다. 설정 수가 적으므로 검색창은 넣지 않는다. 항목은 제목·짧은 설명·오른쪽 컨트롤을 사용한다. 로컬 선택은 즉시 반영하고 실패할 수 있는 시스템 작업은 처리 결과를 확인한다. 별도 저장 버튼을 요구하지 않는다.

| 화면 | 설정 | 기본값·동작 |
|---|---|---|
| ST1 일반 | 앱을 열 때 | 나만의 공간 / 마지막 화면. 기본 나만의 공간, 화면 복원은 같은 계정에만 적용 |
| ST1 일반 | 로그인 시 실행 | 기본 끔. macOS 등록 상태를 읽고 승인이 필요하면 시스템 설정으로 안내 |
| ST1 일반 | 메뉴 막대에 표시 | 기본 켬. 기존 출석 메뉴 막대 기능과 연결 |
| ST1 일반 | 메인 창을 닫았을 때 | 메뉴 막대가 켜져 있으면 백그라운드 유지, 꺼져 있으면 마지막 메인 창을 닫을 때 종료. ⌘Q는 항상 종료 |
| ST1 일반 | 외부 링크 | 기본 브라우저. 프로젝트 내장 자료 열람과 혼동하지 않도록 ‘프로젝트 자료 열람은 프로젝트 화면에서 엽니다’ 안내 |
| ST2 모양 | 테마 | 시스템 / 라이트 / 다크. 기본 시스템. 선택 즉시 설정·메인·스레드 창·메뉴 막대 팝오버에 반영 |
| ST2 모양 | 본문 크기 | 기본 / 크게. 본문 13 / 15pt, 선택 즉시 적용. 웹 원문은 각 서비스 크기 유지 |
| ST2 모양 | 시스템 접근성 | 동작 줄이기·투명도 줄이기 상태를 읽기 전용으로 표시하고 macOS 접근성 설정 링크. 앱에 중복 토글을 만들지 않음 |
| ST3 알림 | macOS 알림 허용 | 시스템 상태 ‘허용됨 / 꺼짐 / 아직 요청하지 않음’. 요청·시스템 설정 진입을 상태에 맞게 제공 |
| ST3 알림 | 출석 가능 시간 알림 | 기본 켬. 서버에서 확인한 대상·시간으로 예약하는 로컬 알림 |
| ST3 알림 | 앱 실행 중 새 공지·스레드 알림 | 기본 켬, 각각 선택. 현재 앱이 수신한 이벤트만 사용 |
| ST3 알림 | 알림 내용 표시 | 기본 끔. 끄면 사람 이름·공지 제목·메시지 본문을 알림에 노출하지 않음 |
| ST4 개인정보 및 저장 공간 | 위치 접근 | 시스템 상태 표시, 출석 때 필요 시 요청. 이 화면에 가짜 권한 토글을 만들지 않음 |
| ST4 개인정보 및 저장 공간 | 임시 캐시 삭제 | 삭제 대상과 실제 측정한 용량 표시 후 확인. 공지·프로필 캐시 및 다운로드 임시파일만 삭제 |
| ST4 개인정보 및 저장 공간 | 개인 프로젝트 보관 | ‘이 Mac의 내 계정에 저장’ 안내. 원문 발췌·결정·연결 자료·임시 작성 내용은 캐시 삭제에서 제외 |
| ST5 앱 정보 | 버전·빌드·업데이트 | 실제 앱 버전과 빌드, 마지막 확인 시각. 기존 앱 내 업데이트 흐름으로 연결 |
| ST5 앱 정보 | 이용약관·개인정보 처리방침·오픈소스 | 실제 서비스 문서 URL로 기본 브라우저 열기. 시안에 가짜 URL을 넣지 않음 |
| ST5 앱 정보 | 문의하기 | 기존 문의 화면으로 이동, 초안과 개인 데이터 자동 첨부 안 함 |

알림 권한이 꺼져 있으면 세부 선택은 보존하되 비활성화하고 ‘macOS에서 알림을 허용해 주세요’를 표시한다. 앱이 종료된 뒤의 새 공지·스레드 원격 푸시는 기존 1차 범위에 따라 제공하지 않는다. 이미 예약된 로컬 출석 알림과 구분해 안내한다. 메뉴 막대 켬이 Mac의 잠자기를 막는다는 뜻은 아니다.

업데이트는 기존 정책을 따른다. 필수 업데이트·점검을 끌 수 있는 설정이나 자동 설치 토글을 새로 넣지 않는다. 로그아웃·계정 삭제·역할 관리는 앱 설정에 중복 배치하지 않는다.

## 6. 저장 범위와 로그아웃

테마·본문 크기·로그인 시 실행·메뉴 막대는 이 Mac의 앱 설정이다. 시작 화면과 알림 세부 선택은 회원 ID별로 저장해 계정 전환 시 적용 범위가 섞이지 않게 한다. 코드·토큰은 UserDefaults에 저장하지 않는다. OS 알림·위치 권한은 시스템이 관리한다.

LO1은 ‘로그아웃할까요?’와 ‘저장한 개인 프로젝트는 이 Mac에 보관돼요. 작성 중인 내용은 저장한 뒤 로그아웃할 수 있어요’를 보여 준다. ‘취소’가 기본 포커스다. 작성 중인 내용이 있으면 저장·내보내기 또는 명시적 폐기 선택을 먼저 처리하고 실패 시 로그아웃을 진행하지 않는다.

서버 로그아웃을 요청하고 Keychain 인증정보·외부 웹 세션·민감한 메모리 캐시·예약된 계정 알림을 정리한다. 개인 프로젝트 저장소를 잠그고 같은 계정이 다시 로그인할 때만 연다. 다른 계정에 이전 사용자의 내용이나 알림을 보여 주지 않는다. 앱은 로그인 화면으로 돌아가며 설정 창과 계정 데이터가 있는 보조 창도 닫는다. 테마는 유지한다.

서버 로그아웃이 실패해도 로컬 세션은 종료할 수 있다. ‘이 Mac에서는 로그아웃됐어요. 서버 세션 종료는 확인하지 못했어요’ 안내를 제공하고 이미 지운 토큰을 복원하지 않는다. 회원 탈퇴나 서버 계정 삭제 API는 로그아웃에 사용하지 않는다.

## 8. 디자인과 접근성

기존 UMC Color · Mi-fi의 Light·Dark 시맨틱 컬러와 UMC Layout 간격을 재사용한다. 주요 행동은 Teal, 본문은 Neutral, 오류와 로그아웃 확인에만 Error를 쓴다. 한글 글꼴은 기존 Figma의 Noto Sans KR이며 실제 앱은 macOS 시스템 글꼴이다. 본문 13, 설명 12, 화면 제목 22를 기본으로 한다.

프로필 메뉴는 최소 32 높이의 클릭 행, 필수 코드 입력은 40 높이를 사용한다. 이름·학교·역할이 길면 줄바꿈하고 상태를 색만으로 구분하지 않는다. 아바타에는 ‘내 계정 메뉴’ 접근성 이름을 붙인다. 메뉴는 화살표·Enter·Esc, 입력은 Tab·Shift Tab·⌘V·Enter를 지원한다. 비활성 설정에는 이유를 읽을 수 있는 설명을 둔다. 모션은 시스템 메뉴·시트 전환만 사용하고 동작 줄이기를 따른다.

### 팝업 정렬 규칙

권한 등록·등록 완료·로그아웃·캐시 삭제 확인은 사용자가 추가로 제공한 팝업 레퍼런스를 따른다. 폭은 640, 안쪽 여백은 32, 반경은 24다. 제목은 왼쪽 위 22pt 굵게, 설명은 13pt로 두고 오른쪽 위에 32×32 닫기 버튼을 배치한다. 행동 버튼은 높이 40, 간격 12로 오른쪽 아래에 정렬한다. 보조 버튼은 Teal 테두리, 주요 버튼은 Teal 채움이며 로그아웃은 Error 채움을 사용한다. 뒤 화면에는 28% 검정 딤과 약한 그림자를 적용한다. 프로필 메뉴는 항목을 선택하는 팝오버이므로 확인 버튼을 붙이지 않는다.

## 9. Figma 화면과 검수 기준

`- Mid-fi` 페이지의 기존 `00 · 나만의 공간 · 홈`에서 단독 설정 아이콘을 제거하고 계정 메뉴 진입을 연결한다. 새 `09 · 계정 및 앱 설정` 섹션에 Light·Dark 화면을 같은 순서로 배치한다. 이름·이메일·학교·기수·코드·용량·버전은 시안용 예시임을 화면 밖 주석에 명시한다.

| ID | 화면 |
|---|---|
| AM1 | 프로필 메뉴가 열린 대시보드 |
| MP1 | 마이페이지 · 내 정보와 활동·권한 |
| MP1-empty | 등록된 활동이 없는 마이페이지 |
| MP1-updated | 코드 등록 뒤 권한을 갱신한 마이페이지 |
| MP2 | 권한 추가 · 6자리 코드 등록 시트 |
| MP2-error | 권한 추가 · 사용한 코드 오류 |
| MP3 | 권한 추가 완료 · 서버 정보 갱신 결과 |
| ST1 | 설정 · 일반 |
| ST2 | 설정 · 모양 |
| ST2-light / ST2-dark | 라이트·다크를 직접 선택한 상태 |
| ST3 | 설정 · 알림 |
| ST4 | 설정 · 개인정보 및 저장 공간 |
| ST5 | 설정 · 앱 정보 |
| ST4-cache | 임시 캐시 삭제 확인 |
| LO1 | 로그아웃 확인 |

- 계정 아바타에서 AM1로 이동할 수 있다. AM1의 세 항목이 각각 MP1·ST1·LO1로 연결된다.
- 홈 탐색 레일에 단독 설정 아이콘이 없다. 설정 창의 일반 카테고리 아이콘은 제거 대상이 아니다.
- MP1·빈 상태에서 권한 추가가 가능하고 MP2·오류·성공 흐름이 검토 가능하다. 명함 메뉴·교환 기능·역할 직접 선택이 없다.
- 다섯 설정 카테고리가 연결되고 시스템·라이트·다크 테마 선택 결과를 확인할 수 있다.
- 코드 재전송 없이 정보만 새로고침하는 상태, 알림·위치 시스템 권한 거부와 캐시 삭제 범위가 문서에 명확하다.
- 두 테마에서 텍스트 잘림·겹침·대비를 확인하고 클릭 대상과 목적지 프레임이 실제로 존재하는지 검증한다.

Figma 프로토타입에서 예시 데이터로 흐름을 검토한다. OS 설정 변경, 실제 권한 부여·정보 갱신, 서버 로그아웃, 알림 예약·해제, 데이터 보존은 앱 구현 단계에서 검증한다.
