## 목록과 읽기

- **전체 목록.** 별도의 큰 ‘공지’ 제목이나 소개 문구 없이 ‘고정 공지’와 ‘최근 공지’부터 보여 준다. 행에는 제목, 본문 미리보기, 수신 대상·작성자·게시일·조회수(`viewCount`)와 첨부 여부를 표시한다. 푸시 발송 여부를 표시하는 경우 목록의 `shouldSendNotification`을 쓰며, 읽음은 별도 신호로 구별한다. 목록의 첨부 표시는 서버의 `hasImages`·`hasVote`·`hasLinks`를 쓴다. 상세 조회 전에는 사진 수, 투표 마감이나 링크 제목을 추측하지 않는다. 좁은 분할 목록은 미리보기부터 줄이고 제목과 선택·읽음 상태를 유지한다.
- **행에서 고정·해제.** 행에 포인터를 올리거나 키보드 포커스를 두면 핀 버튼이 드러난다. 누르면 고정 섹션으로 이동하고 다시 누르면 최근 공지의 게시일 순위로 돌아간다. 이 동작 중 상세가 열리거나 읽음이 기록되지 않아야 한다. 고정 섹션에는 접기·펼치기와 개수를 제공하고 접어도 고정 상태를 보존한다. 동일 ID를 두 섹션에 중복 표시하지 않는다. 현재 서버의 ‘필독’과 이 고정 동작의 관계는 아래 계약 표에서 다룬다.
- **최근 공지.** 고정 섹션에 속하지 않은 글을 게시 시각(`createdAt`) 내림차순으로 배열한다. 페이지를 추가하거나 고정을 해제해도 이 순서를 지킨다. 서버는 필독 우선 정렬이므로 중간 페이지까지 불러온 상태에서 최신 전체 순서를 보장할 수 없다. 전체 최신순과 서버 페이지의 관계는 아래 계약 표를 따른다.
- **읽음.** 행을 선택하고 `READ` 권한을 가진 본문이 실제 표시되면 `POST /{id}/read`를 보낸다. 첫 목록 표시, 포인터 이동, 미리 가져오기, 선택 취소, 본문 로드 실패에서는 읽음을 보내지 않는다. 요청 중 같은 계정과 공지에서 중복 호출을 합치고, 성공한 ID만 개인 읽음 기록에 반영한다. 새로 고침·창 폭 조절·확대 복귀 때 다시 전송하지 않는다. 읽음 전송에 실패해도 본문은 유지하고 그 공지의 읽음만 다시 시도할 수 있게 한다. 읽지 않음 목록에서 읽은 행이 빠져도 열려 있는 상세는 유지한다.
- **분할과 복귀.** 목록과 본문은 하나의 수직 분할 경계를 공유한다. 사용자는 경계를 드래그하면서 양쪽 내용을 계속 볼 수 있다. 목록과 본문은 각각 스크롤한다. 확대와 분할을 오갈 때 선택 ID, 목록 검색·필터, 고정 접힘, 마지막 분할 폭과 양쪽 스크롤 위치를 유지한다. 같은 글을 다시 조회해 조회수를 올리지 않는다. 새 행을 선택하면 새 글 맨 위에서 읽는다. ‘공지 목록’은 선택을 해제하고 전체 목록으로 복귀한다. 창의 이전·다음 방문 기록과 연결할 때도 삭제되거나 접근이 취소된 글은 다시 열지 않는다.

### 공지 도구와 필터

창 제목 막대 맨 오른쪽에 **아이콘과 ‘공지 도구’ 텍스트**를 함께 표시한다. 첫 진입 때 패널이 열리고 같은 버튼을 누르면 닫힌다. 패널 안에 별도 X 버튼을 두지 않는다. Esc로 닫으면 트리거에 포커스를 돌리고, ⌘F로 검색에 접근할 수 있게 한다. 다른 글을 선택하거나 분할 폭을 조절해도 사용자가 닫은 패널을 강제로 열지 않는다. 검색·빠른 보기·게시 기간·대상 조건이 함께 적용되며 ‘초기화’는 기본 목록으로 복귀한다.

| 도구 | 선택과 결과 |
| --- | --- |
| 검색 | 제목·본문 검색. 한글 조합 중에는 쿼리를 보내지 않고 Return 또는 검색 실행 시 확정한다. 편집 중인 문구와 실제 적용한 검색어를 구별한다. |
| 빠른 보기 | ‘전체’는 권한 내 공지, ‘읽지 않음’은 개인 읽음 기록에 따른 결과, ‘고정’은 고정 섹션에 속한 글. 날짜·대상 필터를 바꿔도 빠른 보기 선택은 유지한다. |
| 게시 기간 | ‘전체 기간’, ‘최근 7일’, ‘최근 30일’, ‘날짜 선택’, ‘기간 설정’. 최근 N일에는 오늘을 포함한다. 날짜 선택은 하루, 기간 설정은 시작일과 종료일을 모두 포함한다. 게시 시각을 표시 시간대의 달력으로 비교하며 종료일 다음 날 0시를 배타 경계로 쓴다. 시작일만 선택한 중에는 이전 적용 결과를 유지하고 종료일까지 정하면 갱신한다. |
| 수신 대상 | 활동 기수와 허용된 조직 범위, 챌린저·중앙 운영진·교내 회장단·교내 파트장을 구분한다. 챌린저의 파트는 전체·기획·디자인·웹 PE·모바일 PE를 제공한다. 서버에서 지원하는 조합만 요청하고 대상 변경으로 무효가 된 하위 조건을 초기화한다. |
| 새 공지 작성 | 현재 기수에서 `canCompose`가 참일 때 표시한다. 누르는 시점에 권한을 다시 확인한 후 작성 화면을 연다. |

최초 조회 중에는 로딩, 정상적인 전체 0건에는 빈 목록, 조건 적용 후 0건에는 조건 초기화를 보여 준다. 로컬 필터에서 불러온 행이 모두 제외됐고 서버에 다음 페이지가 있으면 ‘더 보기’를 유지한다. 연결 실패는 마지막 성공 데이터와 실패한 페이지를 보존하고 재시도한다. 권한 회수 시에는 해당 범위의 목록·본문·패널을 즉시 거둔다. 공통 도구의 기존 구현은 초기 닫힘, 아이콘 전용 트리거, 내부 닫기 버튼을 사용하므로 공지에 적용할 때 다른 탭의 동작까지 바뀌지 않게 한다. ## 상세와 운영 동작

상세 상단에 수신 대상, 실제 공지 제목, 작성자·작성일·조회수를 표시한다. 상단 우측 액션의 순서는 **읽음 현황 → 수정 → 삭제 → AI 요약 → 확대/분할 → 공지 도구**다. 각각 `chart.bar.xaxis`, `square.and.pencil`, `trash`, `sparkles`, `arrow.up.left.and.arrow.down.right`(분할로 복귀할 때 `sidebar.left`) SF Symbol을 쓰고 포인터를 올리면 동작명이 뜬다. 키보드와 VoiceOver에도 같은 이름을 제공한다. 각 권한을 확인하는 동안에는 이전 글의 액션을 노출하지 않는다.

| 동작 | 사용할 수 있는 조건과 처리 |
| --- | --- |
| 읽기 | 서버가 해당 공지에 `READ`를 허용한 사용자. 본문에 있는 블록 제목·목록·인용과 인라인 서식을 렌더링하고 텍스트 선택과 복사를 지원한다. 해석할 수 없는 서식에서도 원문을 읽을 수 있게 한다. |
| 읽음 현황·리마인드 | `CHECK`가 있으면 전체·읽음·읽지 않음 인원수와 상태별 명단을 연다. 읽지 않음에서 수신자를 선택하고 선택 인원 확인 후 발송한다. 상태·조직 필터가 바뀌면 커서와 선택을 비운다. 선택한 사람이 이미 읽었거나 권한이 사라지면 재조회하고 수신자를 다시 확인한다. 빈 선택에서는 발송할 수 없다. |
| 수정 | `EDIT`가 있으면 기존 내용으로 에디터를 연다. 제목·본문·첨부를 원래 값으로 채우고 수신 대상은 읽기 전용으로 표시한다. 서버 PATCH가 요구하는 기존 `mustRead` 값은 보존한다. 기존 공지의 대상은 PATCH 계약에 포함되지 않는다. 저장 성공 후 같은 글에서 변경 결과를 확인한다. |
| 삭제 | `DELETE`가 있으면 휴지통을 표시한다. 삭제할 제목을 확인하고 파괴적 동작을 한 번 더 눌러야 요청한다. 취소하면 원래 글로, 성공하면 목록으로 복귀한다. 오류 시 성공한 것처럼 행을 제거하지 않는다. |
| AI 요약 | 상세가 열린 상태에서 요약 버튼을 누르면 오른쪽 위에 해당 공지 본문 요약을 표시한다. 도구가 열려 있으면 요약으로 교체하고, 도구를 다시 열면 요약을 닫는다. 생성 중·완료·실패(다시 시도)·사용 불가를 구분한다. iOS처럼 Foundation Models의 기기 가용성을 확인한다. 기기 미지원이나 Apple Intelligence 비활성 사유를 안내하고 본문은 계속 읽을 수 있게 한다. 닫기·글 전환·권한 회수 시 생성 작업을 취소하고 이전 글의 요약을 비운다. |
| 확대/분할 | 읽을 수 있는 상세가 있을 때만 표시한다. 아이콘·도움말은 다음에 실행할 동작을 알려준다. 전체 읽기에서도 공지 도구와 권한별 액션은 같은 순서다. |

작성 진입은 macOS의 `/api/v2/member/me` 응답에 있는 시스템 관리자 또는 현재 기수 관리자 여부로 선별한다. 게시 가능 여부는 서버가 선택한 `targetInfo`에 대해 다시 판단한다. 기존 글은 `/api/v1/authorization/resource-permission`의 `NOTICE` 및 공지 ID별 허용 결과를 사용한다. 서버의 수정·삭제는 작성자 또는 시스템 관리자, 읽음 현황은 수신 조직에 대한 관리 가능 범위를 기준으로 평가한다. 따라서 일반 운영진에게 수정·삭제·명단 열람을 일괄 부여할 수 없다. 계정·권한 변경 시 열람자 명단, 편집기, 확인창과 진행 중인 작업을 정리한다. ### 본문 아래 첨부

1. **사진.** 상세의 `images` 순서대로 썸네일을 배치한다. 사진을 누르면 큰 이미지가 열리고 확대·축소한 뒤 닫으면 같은 위치와 썸네일 포커스로 복귀한다. 불러오기·실패를 사진별로 처리한다.
2. **투표.** 제목, 단일·복수 선택, 익명·기명, 마감 시각, 참여 인원, 항목별 표수·득표율과 내 선택을 구분한다. 시작 전과 종료 후에는 읽기만, 진행 중에는 선택·제출·변경·취소가 가능하다. 단일 선택에서 두 번째 선택은 기존 선택을 교체한다. 익명이면 참여자 이름·ID와 명단 진입을 숨긴다. 기명 결과는 서버가 반환한 항목별 참여자 정보가 있을 때만 명단에 연결한다. 제출 후 서버 결과로 갱신하고 실패하면 선택을 보존한다.
3. **링크.** 상세의 `links` 순서대로 표시하고 제목 등 미리보기 정보를 확보하지 못하면 URL 또는 도메인을 보여 준다. 검증한 HTTP(S) 링크는 기본 브라우저로 연다. 링크 미리보기 실패가 다른 첨부나 본문을 가리지 않아야 한다.

목록·미리보기·상세 모두 첨부가 없으면 해당 구획을 생략한다. 옵션별 비율과 참여자 ID는 서버 투표 DTO에 있고 현 macOS 모델에는 옵션 ID·내용·표수만 있다. 기명 명단·득표율을 구현할 때 DTO와 도메인 매핑도 함께 바꾼다. ## 새 공지 작성과 수정

전체 작업 영역에서 **제목 입력 → 수신 대상 → 서식 또는 Markdown으로 본문 작성 → 첨부 → 게시 전 확인** 순으로 진행한다. 상단에 ‘공지 작성’과 같은 대형 제목을 반복하지 않는다. 수신 대상에는 현재 기수, 대상 역할, 선택 가능한 지부·학교·파트가 보이고 선택 결과를 한 줄로 확인할 수 있다. 대상이나 역할을 바꾸면 적용할 수 없는 하위 선택은 요청에서 제외한다. 대상자에게 푸시를 보낼지 선택한다. 새 화면에는 필독 표시나 필독 설정을 두지 않는다. 신규 글은 필독을 적용하지 않고, 기존 글 수정 시에는 기존 서버 값을 보존한다.

| 편집 도구 | 지원 범위 |
| --- | --- |
| 문단 | 제목, 머리말, 부머리말, 본문, 모노. 제목 단계는 Markdown의 `#`, `##`, `###`와 대응한다. |
| 글자 | 굵게, 기울임, 밑줄, 취소선. 선택 범위에 적용하고 선택이 없으면 이어 쓰는 글자에 적용한다. |
| 형광펜 | 보라, 분홍, 주황, 민트, 파랑, 색 제거. 선택 색상과 이름을 함께 제공한다. |
| 목록·인용 | 구분점 목록, 대시 목록, 숫자 목록과 인용구. 대시 목록의 UMC App 직렬화 문자(–)도 읽어야 한다. |
| 링크·첨부 | 본문 링크와 별도 링크 첨부를 구분한다. 사진은 추가·제거하고, 투표는 제목·선택지 2~5개·마감·익명 여부·복수 선택 여부를 입력한다. |
| Markdown 원문 | 같은 본문을 서식 편집 또는 원문으로 수정한다. 밑줄 `<u>…</u>`, 색상 `<mark color="R,G,B,A">…</mark>` 등 UMC App 확장 표기를 보존한다. 모드 전환만으로 공백·문단·이스케이프·미지원 구문이 사라지면 안 된다. |

오른쪽 미리보기는 필요할 때 열고 닫으며, 제목·수신 범위·본문과 첨부 순서를 실제 상세 렌더러로 확인한다. 미리보기 자체는 읽음·조회·투표·게시 요청을 보내지 않는다. 취소 시 수정한 내용이 있으면 계속 작성하거나 버릴 수 있게 한다. 게시 전 확인에서 제목, 실제 수신 범위·파트, 푸시 여부, 첨부와 투표 마감을 검토한다. 이 단계에서 돌아가도 입력값이 보존되며 최종 게시 한 번만 요청한다.

제목과 본문은 공백만 입력할 수 없고 서버 제한은 각각 255자, 3,000자다. 서버로 전송하는 Markdown 문자열을 기준으로 검증하며 링크와 투표 항목도 게시 전에 확인한다. 본문이 게시됐는데 사진·링크·투표 저장이 일부 실패하면 기존 게시 ID와 성공 단계를 유지한다. 결과를 알 수 없으면 게시 결과를 조회하고, 본문을 새로 만드는 대신 같은 공지의 남은 단계부터 복구한다. 기존 게시 요청의 회복 기록은 계정과 환경별로 분리한다. [macOS 작성·재시도](../../UMCDesk/Features/Notice/Presentation/Sources/NoticeComposer.swift) · [발행 기록](../../UMCDesk/Features/Notice/Domain/Sources/NoticePublicationJournal.swift)

## 서버 계약과 구현 시 결정할 항목

서버 기준 경로는 `/api/v1/notices`다. 서버와 macOS의 데이터 범위가 다를 때는 다음 표에 맞춰 화면에 표시할 수 있는 범위를 판단한다.

| 요구 | 확인된 계약 | macOS 구현 기준 |
| --- | --- | --- |
| 찾기·최근순·날짜 | 목록과 `/search`는 `gisuId`·`noticeTab`이 필요하고 검색은 `keyword`로 제목·본문을 찾는다. 서버는 `mustRead DESC, createdAt DESC`로 페이징하며 날짜·최신순 전환 필드는 없다. | 서버 필터·검색을 먼저 적용한다. 현재 macOS는 한 번에 20건을 요청한다. 가시 범위 전체의 최근순·기간별 결과가 필요하면 모든 페이지를 읽어 정렬·필터링하거나 서버에 정렬·날짜 쿼리를 추가해야 한다. 일부 페이지만 처리한 시점에는 범위를 알리고 전체 0건·전체 최신순으로 단정하지 않는다. |
| 고정 | 작성·수정의 `mustRead`는 수신자에게 적용되는 필독 속성이다. 공지별 개인 북마크·독립 고정·수동 순번 API는 확인되지 않았다. | **고정의 공유 범위와 조작 권한은 구현 전 결정이 필요하다.** 개인 고정이면 계정·환경별 로컬 ID를 사용하거나 기기 간 동기화 계약을 추가한다. 공용 고정이면 조작 권한·수신자 영향·필독과의 관계를 먼저 확정한다. 행의 핀만 보고 기존 필독 PATCH를 실행하지 않는다. |
| 읽음·읽지 않음 | 상세 GET은 조회수를 올린다. 읽음 기록은 별도 `POST /{id}/read`가 필요하며 목록·상세에 내 `isRead`가 없다. `shouldSendNotification`은 알림 발송 여부다. | 현재 `readIDs`는 메모리 내 확인 기록이다. 서버 성공 기록을 계정·환경별로 보존하면 이 Mac에서 확인한 읽음 기준으로 필터링할 수 있다. 다른 기기의 기록과 설치 전 상태까지 일치시키려면 서버에서 개인 읽음 필드나 조회 수단을 제공해야 한다. 이 범위를 사용자에게 밝히고, 로컬에 없는 값을 서버 미열람 확정으로 표현하지 않는다. |
| 읽음 현황·발송 | `GET /{id}/read-statics`(서버 경로 철자)는 전체·읽음·미열람 **집계**를 반환한다. `GET /{id}/read-status`는 `READ`·`UNREAD` 상태, 조직 필터와 커서로 **명단**을 조회한다. `POST /{id}/reminders`는 비어 있지 않은 `targetIds`에 challenger ID를 받는다. | 개별 읽음 상태를 운영 명단에서 역산하지 않는다. 발송 직전에 `CHECK`와 선택 대상이 여전히 미열람인지 확인한다. ‘미열람 전체’를 제공할 경우 필터 결과의 마지막 커서까지 ID를 모은 뒤 정확한 인원수를 확인한다. |
| 본문·첨부·투표 | 본문 생성 후 사진·링크·투표를 별도 요청으로 연결한다. 본문 PATCH는 제목·내용·필독을 받는다. 투표 응답은 `POST /{id}/votes/responses`, 변경은 PUT, 취소는 PUT에 빈 `optionIds`를 준다. | 첨부 수정은 각 엔드포인트를 사용한다. 편집·미리보기와 게시에 같은 Markdown 원문을 쓴다. 선택과 실제 투표 제출을 분리하고 마감·권한 오류 시 상세를 갱신한다. |
| 요약 | 공지 조회·작성 API에는 AI 요약 필드나 생성 요청이 없다. | 지원 기기의 Foundation Models를 사용한다. 지원 여부·요약 실패가 원문의 가용성이나 읽음 기록에 영향을 주지 않게 한다. |
