## 창 폭과 글자 배율로 배치 결정하기

1단계에서 재현한 셸을 전제로 창 너비 W, Workspace 너비 S=W−64, 원본 본문에 실제 남는 14pt를 제외한 콘텐츠 너비 C=S−14−2P를 쓴다. 제안 좌우 패딩 P=clamp(16,(S−784)/8,40)pt, 상하 24pt다. 따라서 W=1040이면 S=976, P=24, C=914이고 W=1440이면 S=1376, P=40, C=1282다. 14는 원본의 본문·부모 차이다. 실제 스크롤 컨테이너가 이미 그 폭을 제외했다면 다시 빼지 않는다. 독립 고객센터 창에서는 실제 제안 폭을 입력한다. 폭 560까지 허용하는 현재 창에서도 레일이 없는 컨테이너에서 64를 일괄 차감하지 않는다.

s는 앱 글자 배율이다. 두 열 사이 간격은 24pt로 유지하고, **콘텐츠 실폭 C가 아래 두 최소폭 합계 + 24 이상일 때만** 두 열을 쓴다. 남는 너비는 참조 비율로 나누되 좌·우 최소폭을 먼저 보장한다. 왼쪽 폭은 clamp(왼쪽 최소, (C−24)×왼쪽 비율, C−24−오른쪽 최소), 오른쪽은 나머지다. 축소 시 모든 창의 가로 스크롤로 해결하는 대신 읽기·조작 순서를 유지한다.

- **운영 표**는 보조 패널과 독립적으로 실제 표 폭 B를 판정한다. B≥900s는 문의·상태·담당자·라벨·날짜와 기존 팀 정보를 표시한다. 640s≤B<900s는 제목·상태·담당자를 열로 두고 팀·라벨·날짜를 제목 아래 두 번째 줄부터 감싼다. B<640s는 한 항목에서 제목 → 상태·담당자 → 팀·라벨·날짜 순으로 줄바꿈한다. 모든 구간에서 선택·Return·기존 필터·건수를 유지한다. 1040의 s=1에서 보조는 아래로 내려가지만 B=914면 표 자체는 전체 열이다. 표 내부 패딩이 있으면 패딩을 제외한 B로 다시 판정한다.
- **팀 모달**의 외폭 D=min(816,W−32), 내부 양끝 25씩, 열 간격 12다. D−50≥2×300s+12일 때 두 열, 아니면 한 열이다. s=1에서 D=662가 경계이며 D=816이면 원본 377×2가 들어간다. s=1.5/2에서 필요한 D=962/1262이므로 두 창 모두 한 열이다. 셀 최소 높이 96, 내용 증가 시 확장한다. 제목과 닫기는 상단, 선택지 영역만 세로 스크롤하며 최대 모달 높이는 사용 가능한 창 높이−32다. Esc·취소는 기존 팀 선택 유지, 선택 확정은 Q3의 받는 팀 컨트롤로 복귀한다.
- **도구 팝오버**는 기본 폭 min(390, 안전 영역 폭−32)와 원래 패딩 20·간격 14·반경 16·검정 13% 그림자를 사용한다. 후보 위치는 원본의 호출 버튼에 정렬하고 창 가장자리 여유 16을 확보하는 쪽으로 뒤집거나 이동한다. 가로 여유 422에서 기본 폭, 그 아래에서는 내부 텍스트를 감싼다. 세로는 방향별 공간이 콘텐츠 높이+16 미만이면 반대쪽, 양쪽 모두 부족하면 큰 쪽에 놓고 내부를 스크롤한다. 버튼을 확대해도 뒤의 목록은 움직이지 않는다. Q5 담당자/라벨은 각 처리 필드에 붙이고 Q3만 딤 모달로 연다.
- **대화와 작성**은 본문 스크롤과 입력·전송 영역을 형제 뷰로 배치한다. 입력 영역에 실제 필요한 높이를 먼저 배정해 마지막 메시지·폼 필드가 가려지지 않도록 한다. 일반 대화 한 줄 입력의 Return 전송은 유지한다. 작성 본문은 여러 줄, 폼 콘텐츠는 세로로 스크롤한다. 콘텐츠에 제안된 세로 높이에서 하단 조작부를 배정하고 160s pt의 읽기 영역도 남지 않으면 조작부를 본문 마지막으로 이동해 한 스크롤로 탐색한다. 160s 경계의 같음은 고정 조작부 쪽이다. 한 열에서 도움/운영 보조는 주 내용 다음에 두며 Q3에서는 제출 직전에 참고 정보를 둔다.
- **전환점 검수**는 Light/Dark 각각에서 표의 C값과 B=640s·900s, D=50+600s+12, 팝오버 가용 폭 422, 하단 잔여 높이 160s의 −1/정각/+1pt를 입력한다. 같을 때 넓은 쪽 정책, 바로 아래에서 좁은 쪽 정책을 선택한다. D의 상한보다 큰 경계는 실제 창에서 도달할 수 없으므로 순수 배치 판정과 실제 한 열 결과를 나눠 검증한다. P의 16/40 포화점 S=912/1104도 양쪽에서 검사한다.

### 구현에서 구분할 기존 토큰과 문의 전용 치수

[현재 타이포 코드](../../UMCDesk/Core/DesignSystem/Sources/UMCTypography.swift)의 title2Bold는 20/26, bodyRegular는 12/16.8, headlineRegular는 14/19.6이다. 위 표의 목표 크기·행간과 일치하지 않는 역할은 문의 전용 스타일로 매핑한다. 기존 umcFontFamily/umcFontDesign의 사용자 선택 우선순위와 Pretendard 기본값을 재사용한다. 공통 modifier가 이미 앱 본문 배율을 적용하는 역할에는 s를 한 번 더 곱하지 않는다. 화면 제목처럼 공통 스타일이 본문 설정을 따르지 않는 역할은 문의 전용 스타일에서 글자 배율을 한 번 적용한다. 위계 차이를 유지하면서 확대 시 문구가 잘리지 않도록 한다. 자간은 개선 문구 전체 0pt, 버튼·아이콘의 기본 포커스 링을 보존한다.

| 배치 선택 | 검토한 대안 | 채택 이유와 기능 영향 |
| --- | --- | --- |
| 한 열에서 도움을 본문 뒤로 이동 | 별도 도움 메뉴 | 검색·FAQ 사용 뒤 안내가 같은 스크롤에 남는다. 검색 API·정렬·결과 건수는 기존 경로를 따른다 |
| 한 열에서 Q6 편집을 선택 경로로 표시 | 양쪽 패널 가로 스크롤 | 동시 비교가 어려운 폭에서 편집 필드를 온전히 읽을 수 있다. 선택 복귀에 안정 ID만 추가로 사용한다. 저장·발행 계약은 그대로다 |
| 한 열에서 운영 표를 다중 행으로 전환 | 낮은 우선순위 열 삭제 | 팀·라벨을 봐야 하는 운영자가 상세를 반복해서 열지 않아도 된다. 원래 데이터와 필터를 재사용한다 |

## 상태 보존과 서비스 경계

일반 고객센터의 FAQ 읽기와 준비 중인 문의 서비스, 데이터 미리보기 창의 로컬 fixture를 기존 분기대로 제공한다. fixture의 팀 두 종류·로컬 행·운영 컨트롤이 계정 권한이나 서버의 팀 목록을 증명하지 않는다. 1단계 팀 선택의 여덟 항목은 시안 재현용이다. 계약을 확인하기 전 일반 창에서 배정·답변·공개·첨부·해결 집계 성공을 표시하지 않는다. 아래 비동기 피드백은 실제 해당 계약이 연결될 때 적용할 **2단계 추가 제안**이다.

| 상황 | 표시·사용자 행동 | 보존·종료 조건 |
| --- | --- | --- |
| 최초 조회 / 재조회 | 기존 값이 없을 때만 ‘문의를 불러오는 중’과 진행 표시. 이미 보던 목록은 그대로 두고 갱신 상태만 안내 | 최신 검색어·필터에 해당하는 응답만 표시. 조회를 취소해도 선택·작성값 유지 |
| 데이터 0건 / 조건 0건 | 내 문의는 ‘아직 등록한 문의가 없어요’와 가능한 작성 경로. FAQ·운영 필터 0건은 적용 검색어·필터 및 다시 검색/조건 해제 | 조회 성공 때만 0건. 권한 거절·연결 실패를 빈 화면으로 치환하지 않는다 |
| 읽기 실패 | 해당 목록·상세에 오류, 마지막 성공값이 있으면 함께 표시, ‘다시 불러오기’ | 현재 범위 조회만 재시도. 전송·배정·공개·발행을 호출하지 않는다 |
| 쓰기 중 / 명확한 쓰기 실패 | 누른 동작만 ‘보내는 중’ 등으로 표시하고 같은 작업의 중복 클릭·단축키를 차단한다. 확정 실패는 동작명과 ‘다시 보내기’ 등 해당 쓰기만 제공 | 입력·팀·첨부와 포커스 보존. 사용자의 명시적 재시도 한 번만 수행. 다른 티켓의 응답이 현재 입력을 지우지 않는다 |
| 일부 성공 / 결과 불명 | 접수 성공·첨부 실패처럼 서버가 구분해 준 결과만 개별 표기. 쓰기 성공 후 목록 갱신 실패라면 ‘접수했어요. 목록을 다시 불러와 주세요’ | 확인된 성공 작업 재전송 금지. 재조회 후 기존 항목·요청 상태 확인. 서버에서 결과 확인·중복 방지를 보장할 수 없는 결과 불명은 쓰기 재시도 노출을 유보하고 확인 가능한 조회 경로만 제공 |
| 권한 확인 전 / 거절 / 회수 | 확인 전 운영 쓰기 잠금. 명시적 거절은 접근 안내와 허용된 경로로 복귀. 회수 시 열려 있는 운영 메뉴·모달을 닫고 보호 정보를 화면·접근성 트리에서 제거 | 계정·권한 경계 밖에 운영 초안·목록을 남기지 않는다. 진행 중이던 요청의 성공을 추정하지 않는다. 개인 작성 초안은 같은 사용자·허용된 문의 범위에서만 보존 |
| 취소·뒤로·전환 | 메뉴는 임시값 취소, Q4에서 뒤로는 진입점으로, 작성 중 상세 열람·폭 전환은 초안 유지. 미저장 작성 포기 시 ‘계속 작성/작성 취소’ 선택 | 작성 취소 확정 때만 해당 로컬 초안 폐기. 이미 보낸 요청은 화면을 닫아도 취소 완료로 표시하지 않는다 |

현재 fixture의 티켓 ID·답변 ID, 추가 순서·작성자·생성 시각을 유지한다. 공백만 있는 답변은 보내지 않으며 종료 문의는 소유한 문의자의 새 메시지로 재개한다. 운영자의 종료 건은 읽기 전용이다. FAQ 초안 수정·로컬 검증·발행 스냅숏·보관을 한 동작으로 합치지 않는다. 팀 배정·대표 질문·처리 이력의 서비스 근거는 원본 문서의 #157/#171 경계를 따른다. 화면 폭·배율·테마를 상태 식별자에 넣지 않는다. 선택한 티켓과 FAQ·행 포커스는 안정 ID로, 작성 내용·팀과 메뉴의 임시 라벨은 같은 문의의 상위 상태로 소유한다.

## 키보드와 접근성 수용 동작

- **검색**. 검색창 → 결과 → 상세로 이동한다. 기존 Return/↓ 결과 포커스, 선택 행 Return 상세 열기, Esc 목록 복귀를 유지한다. 검색 입력 중 marked text가 있으면 Return·↓·Esc는 입력기에 먼저 전달한다. 조합 확정 이벤트로 동시에 제출하거나 행을 열지 않는다. 검색 포커스와 상태를 검색어별로 재생성하지 않는다.
- **작성·대화**. Tab/Shift+Tab은 문서 순서를 양방향으로 지난다. Q3는 팀→제목→본문→지원되는 첨부→참고 자료→취소·보내기, Q2는 대화 탐색→입력→전송이다. 여러 줄 본문의 Return은 줄바꿈, 단일행 답변에서 조합이 끝난 Return은 유효한 경우 한 번 전송한다. Space는 포커스된 버튼·체크만 작동한다. 한글 조합 중 Space/Return으로 버튼이 작동하지 않아야 한다.
- **팝오버·모달**. 호출 컨트롤 ID를 보관하고 열린 영역의 제목 또는 현재 선택에 포커스를 둔다. 팀 모달의 배경 컨트롤은 탐색에서 제외한다. Esc는 가장 안쪽 메뉴→모달→상세 순으로 한 단계만 닫는다. 포커스는 호출 버튼으로, 호출 행이 삭제된 경우 목록 제목/검색으로 돌린다. 크기 전환만으로 선택·메뉴 임시 체크를 확정하지 않는다.
- **VoiceOver**. 제목은 heading, 현재 탭·행은 selected trait, 버튼 label은 행동명, value는 선택된 팀·상태다. 대화 한 건은 발신자·시간·내용 순서로 읽고 실제 링크·첨부 행동은 별도 탐색한다. 상태 아이콘·장식 아바타는 중복 낭독하지 않는다. 대기/해결 안내는 상태가 실제로 바뀔 때 한 번만 알린다. 텍스트 선택과 링크 조작도 접근 가능해야 한다.
- **시각 접근성**. 선택·미배정·읽기 전용을 텍스트·체크·잠금과 함께 표시한다. 실제로 쓰인 텍스트/면 조합의 목표 대비는 일반 글자 4.5:1, 큰 글자 3:1, 컨트롤·포커스 경계 3:1이다. 혼합 알파와 Light 강제 예외는 최종 합성색으로 검증한다. 대비 증가 시 시스템 포커스 링·경계를 보강하고 투명도 감소 시 시스템 불투명 표면으로 바꾸되 모달 경계를 유지한다. 추가 이동 애니메이션은 두지 않고 Reduce Motion에서 기본 전환도 위치 이동 없이 즉시 상태를 바꾼다. 대비·VO 실측 결과는 구현 시 기록한다.
