## 목적과 구현 범위

설정 섹션의 20개 화면·상태를 SwiftUI로 구현한다. 사용자는 마이페이지에서 자신의 프로필과 활동을 확인하고 링크를 편집하거나 운영진이 발급한 코드를 등록한다. 앱 설정에서는 이 Mac의 실행 방식·화면·권한·캐시를 관리한다.

이번 작업은 Settings Feature를 새로 만들고 실제 계정 API와 macOS 기능을 연결한다. 설정을 열 때마다 가짜 계정을 로그인시키거나 예시 권한을 실제 계정에 저장하지 않는다. 현재 Auth는 화면 검증만 구현되어 있으므로 유효한 토큰이 없으면 마이페이지에 로그인 필요 상태를 표시한다. 로그인 연결은 기존 [#43](https://github.com/UMC-PRODUCT/umc-product-macOS/issues/43), [#44](https://github.com/UMC-PRODUCT/umc-product-macOS/issues/44)의 범위다.

공지·채팅·출석 이벤트와 개인 프로젝트 저장소도 아직 없다. 설정 화면은 해당 기능을 제공한다고 표시하지 않는다. 이름·학교·사진·비밀번호·이메일 변경이나 탈퇴는 이 Figma 섹션에 없으므로 추가하지 않는다.

## 공통 계약과 담당 경계

의존 방향은 `SettingsPresentation → SettingsDomain ← SettingsData`다. 앱의 `AppDependencies`가 객체를 연결한다. A는 Domain·Data·환경 설정·시스템 동작·Tuist·앱 통합을, B는 View·ViewModel·리소스·화면 테스트를 담당한다. 두 구현자가 다음 공개 계약을 먼저 맞춘다. 파일 안의 세부 배치는 주변 코드에 맞게 조정할 수 있다.

| 타입 | 책임과 공개 계약 |
|---|---|
| `SettingsProfile` | `id`, `name`, `nickname`, `email`, `schoolName`, `profileImageURL`, `links`, `activities`. 식별자와 기수는 `String`, URL은 검증된 `URL?`. 계정 데이터는 메모리에만 유지 |
| `SettingsProfileLinks` | `github`, `linkedIn`, `instagram`, `blog`, `personal`의 문자열 값. 빈 값은 미등록 |
| `SettingsActivity` | 안정적인 `id`, `generation`, `part`, `roles`. 원래 서버 값을 보존하고 표시명은 별도로 계산 |
| `SettingsRepository: Sendable` | `fetchProfile() async throws -> SettingsProfile`, `updateProfileLinks(_ links: SettingsProfileLinks) async throws -> SettingsProfile`, `registerChallenger(code: String) async throws`, `logout() async throws` |
| `SettingsUseCase: Sendable` | Repository와 같은 네 메서드. `DefaultSettingsUseCase`가 링크·코드 검증 후 Repository에 위임 |
| `SettingsPreferences` | Domain의 `@MainActor @Observable` 로컬 환경 모델. `init(defaults: UserDefaults)`로 격리 테스트 가능. `theme`, `bodyTextSize`, `launchPage`, `showsMenuBar`, 알림 종류별 수신 여부·내용 표시를 저장 |
| `SettingsSystemActions` | Domain의 `@MainActor` protocol. 시스템 상태 조회, 로그인 항목 변경, 알림 허용 요청, 시스템 설정 열기, 임시 캐시 조회·삭제, 릴리스 조회, 계정 알림 정리를 제공. SwiftUI 타입은 노출하지 않음 |
| `MacSettingsSystemActions` | Data의 실제 macOS 구현. AppKit·ServiceManagement·UserNotifications·CoreLocation·FileManager를 사용 |
| `SettingsViewModel` | Presentation의 `@MainActor @Observable`. UseCase·Preferences·SystemActions를 주입받고 프로필 로딩·편집 초안·코드 단계·토스트·검색·시스템 작업 상태를 소유 |
| `SettingsView` | 공개 진입점 `init(viewModel: SettingsViewModel)`. 화면은 ViewModel을 `@State`로 소유하고 하위 입력은 `@Bindable`로 연결 |

`SettingsSystemActions`의 메서드는 다음을 기준으로 확정한다. 상태 모델은 값 타입이며 테스트에서는 실제 시스템 설정을 바꾸지 않는 구현을 주입한다.

```swift
@MainActor public protocol SettingsSystemActions {
    func status() async -> SettingsSystemStatus
    func setLaunchAtLogin(_ enabled: Bool) async throws
    func requestNotificationAuthorization() async throws
    func openSystemSettings(_ destination: SettingsSystemDestination) -> Bool
    func cacheSize() async throws -> Int64
    func clearCache() async throws
    func latestRelease() async throws -> SettingsRelease?
    func clearAccountNotifications() async
}
```

공개 ViewModel 생성자는 `init(useCase: any SettingsUseCase, preferences: SettingsPreferences, systemActions: any SettingsSystemActions)`다. ViewModel은 세 의존성을 읽기 전용 속성으로 제공한다. Profile의 `id/name/nickname`은 `String`, `email/schoolName`은 `String?`이며 Activity의 `id/generation/part`는 `String`, `roles`는 표시용 `[String]`이다.

Preferences의 공개 속성은 `theme: SettingsTheme`, `bodyTextSize: SettingsBodyTextSize`, `launchPage: SettingsLaunchPage`, `showsMenuBar`, `attendanceNotifications`, `noticeNotifications`, `threadNotifications`, `showsNotificationContent`다. 마지막 다섯 속성은 `Bool`이다. enum은 각각 `system/light/dark`, `standard/large/extraLarge`, `login/myPage/settings`이며 기본값은 `system/standard/login`이다. 메뉴 막대와 세 종류 알림 수신은 기본 true, 알림 내용 표시는 기본 false다. 실제 없는 알림 기능의 제공 여부와 이 선호값은 구분한다.

`SettingsSystemStatus`의 필드는 `loginItem: SettingsLoginItemStatus`, `notifications: SettingsNotificationStatus`, `location: SettingsLocationStatus`다. enum 값은 로그인 항목 `disabled/enabled/requiresApproval/unavailable`, 알림 `notDetermined/denied/authorized/provisional`, 위치 `notDetermined/denied/restricted/authorized`다. 시스템 목적지는 `loginItems/notifications/location/accessibility`, 릴리스 필드는 `tag: String`, `url: URL`로 정한다.

`SettingsSystemStatus`는 로그인 항목 상태, 알림 권한, 위치 권한을 담는다. 각 상태 enum에는 미결정·허용·거부 등 실제 API 상태를 표현할 값을 둔다. `SettingsSystemDestination`은 로그인 항목·알림·위치·접근성이다. `SettingsRelease`는 표시용 태그와 확인된 HTTP(S) 릴리스 URL을 담는다. 구체적인 시스템 오류는 사용자에게 안전한 안내로 변환한다.

## 진입과 화면 구조

macOS `Settings` scene으로 앱 메뉴의 설정과 `⌘,`를 제공한다. 로그인 화면에서도 설정을 열 수 있다. 마이페이지와 다섯 설정 탭은 같은 탐색 셸에서 접근하며 프로필 메뉴에는 마이페이지·설정·로그아웃을 둔다. 미인증 상태에서는 로그아웃과 계정 편집을 노출하지 않는다.

Figma의 어두운 앱 레일과 밝은 콘텐츠 영역, 설정 안의 보조 사이드바를 유지한다. 아직 없는 기능으로 이동하는 레일 항목을 정상 동작하는 것처럼 만들지 않는다. 네이티브 창 제어 버튼은 macOS에 맡긴다. 뒤로·앞으로는 실제 탐색 이력이 있을 때만 동작하고 새로고침에는 툴팁과 접근성 이름을 제공한다.

일반·모양·알림·개인정보 및 저장 공간·앱 정보의 사이드바 검색은 제목과 설명을 로컬에서 검색한다. 공백을 정리하고 대소문자를 구분하지 않으며 결과를 선택하면 해당 탭으로 이동한다. 빈 검색어는 전체 탭, 결과가 없으면 Figma의 빈 상태를 표시한다. 네트워크 검색이나 새 인덱스 패키지는 필요 없다.

창과 콘텐츠의 기본 치수는 `757:12600`, 프로필 메뉴는 `776:17282`를 기준으로 한다. 이후 사용자가 더 얇은 레일을 요청하고 GPT 창의 참고 이미지를 제공하여 레일만 위 표의 값으로 변경했다. 원래 Figma의 왼쪽 영역 92pt 대신 52pt를 사용하며 설정 보조 사이드바 271pt와 카드 최대 폭 960pt는 유지한다.

2026-10-20의 추가 요청에 따라 창 제어 버튼과 탐색 버튼을 같은 네이티브 툴바 줄에 배치한다. 이 기준은 Settings 셸을 창 최상단까지 확장하던 이전 설계를 대체한다. 본문은 타이틀바와 툴바의 안전 영역을 존중하고 기존 커스텀 상단 바와 그 아래 구분선은 제거한다. 기본 창 크기는 1440×960pt, 최소 크기는 1040×720pt로 유지한다. 캡처 이미지의 픽셀 크기만 보고 창을 줄이거나 전체 UI에 축소 배율을 적용하지 않는다.

닫기·최소화·확대는 실제 macOS 창 버튼을 유지한다. 창 버튼을 위해 두었던 레일 상단의 40pt 공간은 제거하고 타이틀바 높이를 임의의 상단 여백으로 보정하지 않는다. 창 버튼의 크기와 위치는 macOS가 관리하며 복제하거나 수동으로 재배치하지 않는다. 시스템 화면 공유 표시가 캡처에 나타나더라도 앱에서 숨기지 않는다.

메인 `WindowGroup`과 별도 `Settings` scene은 `.windowStyle(.titleBar)`와 `.windowToolbarStyle(.unifiedCompact(showsTitle: false))`를 사용한다. Settings의 뒤로·앞으로는 `ToolbarItemGroup(placement: .navigation)`에, 마이페이지 새로고침은 `.primaryAction`에 배치한다. 기존 액션·단축키·비활성 조건·접근성 레이블을 유지하되 툴바 버튼의 고정 프레임과 커스텀 원형 배경은 제거한다. `.fullSizeContentView`와 `toolbar = nil`을 강제하던 `SettingsWindowChrome`은 삭제하고 `Settings` scene과 `openSettings` 진입은 유지한다. 별도 `Settings` 창은 Scene 설정만으로 설정 창 전용 툴바 스타일이 바뀌지 않아 `SettingsWindowToolbar`에서 실제 창의 `toolbarStyle = .unifiedCompact`와 `titleVisibility = .hidden`만 지정한다. 이 두 속성으로 창 제어 버튼과 탐색 버튼이 왼쪽 한 줄에 놓이는 것을 실제 앱에서 확인했다. 툴바 인스턴스와 안전 영역은 그대로 유지한다.

툴바 배경과 구분선은 macOS 기본 처리를 따른다. 기존 `.toolbarBackgroundVisibility(.hidden, for: .windowToolbar)`와 본문의 상단 `ignoresSafeArea`는 제거한다. 실제 메인 창과 설정 창을 처음 열거나 다시 열었을 때 창 제어 버튼과 탐색 버튼이 같은 줄에 놓이고 본문과 겹치지 않는지 Light·Dark에서 확인한다.

프로필 메뉴는 아바타 옆에 열리는 네이티브 popover로 제공한다. 시안의 헤더·구분선·텍스트 메뉴 구조와 폭을 맞추고, 실제 계정의 기수·학교·역할을 표시한다. 메뉴 행에 시안에 없는 아이콘은 더하지 않는다. 긴 이름과 큰 본문은 줄바꿈으로 수용하며 메뉴를 맞추기 위해 사용자가 저장한 본문 크기를 초기화하지 않는다. 시안 비교용 DEBUG 실행만 기본 배율과 동일한 활동 데이터로 맞춘다.

`GeometryReader`나 측정값을 상태에 되돌리는 방식은 쓰지 않는다. 기본 스택·frame·`containerRelativeFrame`으로 배치한다. 체크박스는 `UMCCheckboxStyle`, 시안의 스위치는 네이티브 `.switch`를 사용한다. 키보드 포커스·Space·Return·Escape와 VoiceOver 레이블을 유지한다. 색상만으로 선택·오류를 전달하지 않는다.

설정 전환에 별도 장식 모션을 추가하지 않는다. 필요한 짧은 전환과 토스트는 Reduce Motion을 따르고 Reduce Transparency가 켜지면 불투명 토큰 표면을 사용한다. SF Symbol은 `Image(systemName:)`로 렌더링한다. 테마 미리보기·앱 아이콘·카카오 아이콘은 Figma에서 PDF로 받은 Asset을 사용한다. 실제 프로필 사진은 서버 URL을 사용하고 시안 사진은 DEBUG fixture에만 둔다.

## 계정 데이터와 API

### 조회와 프로필 표시

`GET /api/v1/member/me`의 `MemberInfoResponse`를 읽는다. `profile`은 다섯 링크가 모두 null인 객체일 수 있다. `schoolId`·`schoolName`·`profileImageLink`와 활동 내부 필드도 nullable을 허용한다. 역할은 최상위 `roles`를 기수·챌린저 식별자에 맞춰 활동과 연결한다. 이 서버 조립 경로는 활동 내부 `roles`를 채우지 않으므로 거기에만 의존하지 않는다.

서버 `JacksonConfig`는 숫자를 문자열로 직렬화한다. id·gisu 등은 전 계층 `String`으로 유지하며 flexible decoding을 사용한다. Response DTO에는 custom `init(from:)`와 `encode(to:)`를 구현한다. 알 수 없는 파트·역할 값은 데이터를 버리거나 크래시를 내지 않고 원문 기반의 안전한 표시명으로 남긴다. 화면에 표시하는 역할을 새로운 권한 판정 근거로 사용하지 않는다.

초기 조회에는 `Loadable`을 쓰고 새로고침 중에는 마지막 성공 데이터를 유지한다. 서로 다른 요청의 응답이 뒤집히거나 로그아웃 후 응답이 돌아와도 이전 계정 정보를 복구하지 않도록 작업 취소와 요청 세대를 확인한다. 인증 실패로 세션이 끝나면 편집 초안·모달·알림 메시지까지 정리한다.

### 링크 편집

`PATCH /api/v1/member/profile/links`의 요청은 `{ "links": [{ "type": "GITHUB", "link": "https://..." }] }`다. 타입은 `GITHUB`, `LINKEDIN`, `INSTAGRAM`, `BLOG`, `PERSONAL`이다. 서버는 기존 다섯 값을 먼저 비우므로 전체 폼의 비어 있지 않은 링크를 모두 보낸다. 빈 배열은 전체 삭제다.

편집창을 열 때 서버 값으로 초안을 만들고 취소하면 버린다. 앞뒤 공백을 제거하며 입력된 값은 host가 있는 HTTP(S) URL인지 확인한다. `javascript:`, `file:`, 사용자명·비밀번호가 포함된 URL은 허용하지 않는다. 유효하지 않으면 필드 가까이에 오류를 표시하고 서버에 보내지 않는다. 저장 중에는 중복 제출을 막으며 성공 응답으로 화면을 갱신한다. 실패하면 입력값을 유지한다.

### 챌린저 코드

`POST /api/v1/challenger-record/member`에 `{ "code": "A7B2C9" }`를 보낸다. 서버 DTO가 요구하는 조건은 공백이 아닌 정확히 6자리다. 코드는 불투명한 값으로 취급하여 임의로 대문자로 바꾸거나 숫자로 변환하지 않는다. 붙여넣기 앞뒤 공백만 정리하고 6자리일 때 등록을 허용한다.

등록 성공 뒤 `/member/me`를 다시 읽어야 완료 화면에 최신 활동과 역할을 표시할 수 있다. POST는 성공했으나 GET이 실패하면 “코드는 등록됐어요. 최신 정보를 다시 불러와 주세요.”를 표시하고 재조회만 제공한다. 이미 소비한 코드를 자동 재전송하지 않는다. 등록 실패는 서버 오류 코드에 맞게 안내하며 모든 실패를 “이미 사용한 코드”라고 표시하지 않는다.

### 로그아웃

확인창에서 취소하면 아무 작업도 하지 않는다. 확인하면 먼저 `NetworkClient.logoutReturningRefreshToken()`으로 진행 중인 토큰 갱신을 마무리하고 로컬 토큰과 역할·DI 캐시를 정리한다. 그 과정에서 마지막으로 확인한 refresh token을 받아 `POST /api/v1/auth/logout`에 무인증 요청으로 보낸다. 요청 전에 읽은 토큰을 보관했다가 폐기하면, 그 사이 회전한 새 토큰이 서버에 남을 수 있으므로 이 순서를 지킨다. 서버 폐기 실패를 로컬 세션 종료 실패와 혼동하지 않으며, 로컬 정리에 실패하면 성공 화면을 표시하지 않는다.

현재 Aquila는 logout이 시작되면 새 갱신을 막고 진행 중인 갱신을 취소한 뒤, 저장 작업이 끝날 때까지 기다렸다가 TokenStore를 비운다. 다만 refresh 응답을 받은 뒤 저장하기 전에도 취소 여부를 검사하므로, TokenStore에 저장된 값만 읽으면 방금 발급된 토큰을 놓칠 수 있다. 이를 보완하는 코드는 CoreNetwork 내부에 둔다. TokenStore forwarding proxy와 refresh service가 같은 상태를 공유하고, service가 수신한 미저장 refresh token을 취소 검사 전에 기록한다. 진행 중 HTTP 갱신은 취소를 상속하지 않는 Task로 응답까지 기다린다. 토큰 저장에 성공하면 미저장 기록을 해소하고, clear는 미저장 발급 토큰이 있으면 그 값을, 없으면 저장소의 값을 담아 둔 뒤 실제 삭제에 성공한 경우에만 호출자에게 반환한다.

CoreNetwork의 기존 `logout()`과 새 메서드는 같은 진행 작업을 기다린다. 동시 호출이 서로의 토큰 값을 가져가거나 두 번째 clear로 덮어쓰지 않도록 한 작업의 반환값을 공유한다. 일반 `logout()`은 반환된 토큰을 폐기하고, Settings Repository만 서버 폐기에 사용한다. 토큰은 UserDefaults·로그·문서에 기록하지 않는다. 서버 응답 자체가 네트워크에서 유실된 경우까지 모든 회전 토큰의 폐기를 보장할 수는 없다. 이 한계는 서버의 세션 단위 폐기 계약 없이 해결할 수 없으므로 로컬 로그아웃과 서버 폐기 확인을 구분한다.

Settings의 계정 데이터·초안·진행 요청과 현재 앱의 예약·전달 알림도 정리한다. 메뉴 막대와 다른 설정 창에 계정 정보가 남지 않아야 한다. 일반 환경 설정은 이 Mac의 값이므로 유지한다. 아직 없는 개인 프로젝트 잠금·복원을 구현 완료로 안내하지 않는다.

## 이 Mac의 앱 설정

### 일반

- **앱을 열 때:** 현재 동작하는 로그인·마이페이지·설정 진입점을 선택하고 다음 실행에서 적용한다. 기본값은 기존 로그인 화면이다. Figma의 “나만의 공간”은 해당 화면이 생기기 전까지 선택지에 추가하지 않는다. 계정 화면을 선택해도 인증을 우회하지 않는다.
- **로그인 시 실행:** `SMAppService.mainApp`의 등록·해제와 상태를 사용한다. 등록 실패는 기존 상태로 되돌리고 승인 대기는 “승인 필요”와 로그인 항목 설정 열기로 안내한다. 단순 UserDefaults 값을 성공 근거로 쓰지 않는다.
- **메뉴 막대에 표시:** 실제 `MenuBarExtra` 표시 여부를 즉시 바꾼다. 앱 열기·마이페이지·설정·종료 동작을 제공한다. 출석 상태는 아직 제공하지 않으므로 표시한다고 쓰지 않는다.
- **메인 창을 닫았을 때:** 메뉴 막대가 켜져 있으면 백그라운드 유지, 꺼져 있으면 마지막 앱 창을 닫을 때 종료한다. 앱 수명 delegate가 최신 설정을 읽는다.
- **외부 링크:** 현재 지원하는 기본 브라우저로 연다. 제공하지 않는 브라우저·내장 열람 선택지를 추가하지 않는다.

### 모양

시스템·라이트·다크를 저장하고 앱 창과 설정 창에 함께 적용한다. Auth의 Light 고정 브랜드 패널은 유지한다. 본문 크기는 기본·크게·더 크게의 1.0·1.15·1.3배로 제공하며 본문/설명에 적용한다. 제목·아이콘·컨트롤 전체를 통째로 확대하지 않는다. 타이포 크기 환경값은 CoreDesignSystem에 작은 API로 추가하고 Preview 조정 기능과 곱해 사용한다.

접근성 항목은 시스템의 동작 줄이기·투명도 줄이기를 그대로 따르며 앱 안에 중복 토글을 만들지 않는다.

### 알림

`UNUserNotificationCenter`에서 실제 권한을 읽는다. 아직 결정하지 않았을 때에만 사용자의 명시적 허용 동작으로 권한을 요청하고 거부된 상태에는 시스템 설정 열기를 제공한다. 창이 다시 활성화되면 상태를 재조회한다.

출석·공지·스레드 수신 여부와 내용 표시 선택은 이 Mac에 저장한다. 현재 이벤트 생산자가 없다는 상태를 함께 안내하며 토글만 켜졌다고 알림이 제공된다고 쓰지 않는다. 기존 일정·공지·채팅 기능을 이번 작업에서 새로 만들지 않는다. 이후 생산자가 연결될 때는 설정을 읽어 수신 종류와 본문 노출을 제한해야 한다. 이번 구현으로 원격 푸시가 생기지 않는다.

### 개인정보 및 저장 공간

CoreLocation에서 실제 권한 상태만 읽고 위치를 요청하거나 좌표를 수집하지 않는다. 권한 버튼은 macOS 위치 설정으로 연결한다. 표시를 위해 불필요한 위치 권한 entitlement를 추가하지 않는다.

임시 캐시는 앱의 Caches 디렉터리 아래 전용 `SettingsTemporaryCache`만 대상으로 한다. 실제 파일 크기를 합산하고 삭제 확인 후 이 경계 안의 파일만 정리한다. 경로 탈출·심볼릭 링크를 따라 외부 디렉터리를 삭제하지 않는다. Keychain·UserDefaults·Application Support의 개인 데이터·사용자 Downloads·전체 temporaryDirectory는 삭제 대상이 아니다. 실패는 알리고 완료 후 실제 용량을 다시 읽는다.

현재 개인 프로젝트 저장소는 없으므로 시안의 “내 계정에 보관”·“로그아웃하면 잠그고 복원”을 보장 문구로 복사하지 않는다. “개인 프로젝트는 아직 제공하지 않아요”와 캐시 삭제의 실제 범위를 안내한다.

### 앱 정보

앱 이름·버전·빌드 번호는 Bundle에서 읽는다. `1.0.0 / 100`과 예시 확인 시각을 하드코딩하지 않는다. 업데이트 확인은 이 저장소의 공개 GitHub Releases 정보를 읽고 실제 조회한 태그·페이지와 성공 시각을 표시한다. 자동 설치는 제공하지 않으며 릴리스가 없거나 네트워크가 실패한 상태를 구분한다. 단순 조회 성공만으로 “최신 버전”을 단정하지 않는다.

이용약관·개인정보·카카오 문의는 운영 게시 주소가 확인된 경우에만 연다. 저장소 안의 검토 중 법률 초안을 최종 약관으로 게시하거나 임의의 카카오 채널을 연결하지 않는다. 주소를 확인하지 못하면 해당 항목에 “주소 확인 중”을 표시하고 잘못된 탐색을 막는다. 오픈소스는 현재 의존성의 실제 저장소·라이선스 링크를 보여 준다.

## 검증과 완료 기준

실제 계정·OS 권한을 바꾸는 자동 테스트는 하지 않는다. UseCase와 ViewModel에는 제어 가능한 구현을, 시스템 동작에는 임시 디렉터리·테스트 UserDefaults를 주입한다. 필수 검증은 전체 치환 링크, 잘못된 URL 차단, 6자리 코드, 등록 후 조회 실패, 로그아웃 중 늦게 온 응답, 캐시 외부 파일 보존, 설정 재실행 유지, 검색 결과·빈 결과다. 토큰 갱신은 저장 도중과 응답 수신 전의 두 시점에서 로그아웃을 시작해 최종 발급 토큰이 반환되고 저장소가 비워지는지 확인한다. 동시 로그아웃과 저장소 삭제 실패도 검증한다.

1440×960과 최소 창 크기에서 Light·Dark, 큰 본문, 긴 링크, 활동 없음, 오류 모달을 확인한다. DEBUG에는 20개 시안 상태를 재현하는 fixture/launch argument를 제공하되 일반 Release와 `UMC_PRERELEASE`에는 새 Mock을 포함하지 않는다. 앱·Settings 계층 테스트와 Debug/Release 빌드 결과를 기록한다. 서버 실계정과 서명 앱의 로그인 항목 등록은 별도 수동 확인이 필요하다.

2026-10-20 구현 결과, 전체 89개 테스트와 마지막 UI 보정 후 앱·Presentation 22개 회귀 테스트가 통과했다. 마지막 변경까지 포함한 서명 없는 arm64·x86_64 Release 빌드도 성공했다. 사용자 요청에 따른 52pt 왼쪽 영역과 별도 설정 창의 제목 막대 배경 제거를 실제 앱에서 확인했고, `⌘W`로 닫은 뒤 `⌘,`로 다시 열어도 유지됐다. 일반 Release와 프리배포 설정에 새 Mock 아바타가 포함되지 않는 것도 확인했다.

실계정 서버 변경·실제 OS 권한 변경·서명 앱 로그인 항목 등록과 전체 VoiceOver 수동 점검은 실행하지 않았다. 자동 레이아웃 검사는 주요 6개 화면의 두 창 크기·두 테마를 다루며 전체 20개 상태를 사람이 시각 비교했다는 의미는 아니다. 화면 캡처와 세부 검증 범위는 [구현계획의 검증 기록](../plans/설정_마이페이지와%20앱%20설정_구현계획.md#검증-기록--2026-10-20)에 정리했다.
