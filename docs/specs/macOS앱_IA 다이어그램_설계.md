# UMC macOS 앱 IA 다이어그램

작성일: 2026-09-18
수정일: 2026-09-27
작성자: 제옹(euijjang97)
근거: `docs/specs/macOS앱_전 사용자 데스크톱_설계.md` (2026-09-27 개정)

pen.dev 캔버스에 IA 다이어그램을 그릴 때 프롬프트에 넣는 입력 문서입니다.
화면이 무엇이고 어디서 어디로 이어지고 누구에게 보이는지만 담았습니다.
화면 안의 모양은 이 문서의 범위가 아닙니다.

## 1. 그리는 규칙

- 박스와 화살표로만 그립니다. 와이어프레임이나 화면 목업을 그리지 않습니다
- 이 문서에 있는 노드만 그립니다. 없는 화면을 채워 넣지 않습니다.
  빈 곳이 보이면 6장의 미정 노드로만 둡니다
- 노드 안에는 `ID 이름` 을 적고 배지를 붙입니다. 이름은 이 문서 표기를 그대로 씁니다
- 버튼과 단축키는 노드로 만들지 않습니다. 노드 안 목록으로 적거나 화살표 라벨로 씁니다
- 배치는 가로 방향입니다
  - 맨 위 띠: 전역 흐름(G). 앱 실행에서 메인 창까지 왼쪽에서 오른쪽으로
  - 그 아래 큰 프레임: 메인 창(G4). 왼쪽 끝에 사이드바 여섯 항목을 세로로 두고
    항목마다 가로 한 줄(레인)을 씁니다. 레인 안은 목록 → 상세 → 시트·상태 변형 순서입니다
  - 오른쪽 끝 세로 열: 별도 창(T3)과 앱 밖(X)
- 사이드바 항목은 공지 · 활동 · 스레드 · 프로젝트 · 매칭 · 문의 순서로 고정입니다.
  역할에 따라 항목이 늘거나 줄지 않습니다

## 2. 범례

**노드 모양**

| 종류 | 모양 | 뜻 |
|---|---|---|
| 창 | 굵은 테두리 사각형 | 독립된 macOS 창 |
| 화면 | 사각형 | 목록 컬럼, 상세 컬럼, 인스펙터 |
| 시트 | 둥근 사각형 | 화면 위에 뜨는 시트 |
| 상태 변형 | 점선 사각형 | 같은 화면이 조건에 따라 바뀐 모습. 원래 노드 옆에 붙입니다 |
| 앱 밖 | 회색 평행사변형 | 기본 브라우저, 시스템 인증 창 |
| 미정 | 점선 사각형 + `미정` 태그 | 설계에 위치나 표시 방식이 없습니다(6장) |

**권한 배지** — 노드 왼쪽 위에 색 칩으로 붙입니다. 전체 공개 노드에는 붙이지 않습니다.

| 배지 | 색 | 판정 근거 |
|---|---|---|
| 운영진 모드 | 주황 | 조직 역할(`ManagementTeam`) + 툴바의 운영진 모드 토글 |
| 방 역할 | 보라 | 스레드 상세의 `myRole` (`OWNER`·`ADMIN`·`MEMBER`) |
| 프로젝트 권한 | 파랑 | 서버 `projects/permissions` 의 capability `allowed` |
| 조직 레벨·파트 | 초록 | Plan 파트, 지부장 이상 |

**단계 배지** — 노드 오른쪽 위에 로드맵 단계 숫자를 붙입니다(1 · 2 · 2.5 · 3 · 4 · 5 · 6).
로드맵에 없는 노드에는 붙이지 않습니다.

**화살표**

| 선 | 뜻 |
|---|---|
| 실선 | 같은 창 안에서 이동 |
| 점선 | 시트나 새 창을 연다 |
| 회색 실선 | 앱 밖으로 나간다 |

화살표 라벨에는 트리거를 적습니다(클릭, 더블클릭, 버튼 이름, 단축키, 조건).

## 3. 노드

표기: `ID 이름 — 종류 · 권한 · 단계`. 권한이 `전체` 면 배지를 붙이지 않습니다.

### 3.0 전역 흐름

- **G0 앱 실행** — 시작점
- **G1 업데이트 알림** — 상태 변형 · 전체 · 5
  - 앱을 켤 때 최신 버전을 확인하고 새 버전이 있으면 알림만 띄웁니다
- **G2 점검 화면** — 화면 · 전체
  - 서버 점검 중(503 또는 시스템 상태 조회)이면 앱 전체를 덮습니다
- **G3 로그인** — 화면 · 전체 · 1
  - 카카오 · 애플 · 구글
  - 카카오는 시스템 인증 창(X1)에서 코드를 받아 옵니다
- **G4 메인 창** — 창 · 전체 · 1
  - 툴바: 운영진 모드 토글(운영진 권한이 있는 계정)
  - 메뉴바(단계 5): 새 공지 ⌘N(권한 없으면 비활성) · 새로고침 ⌘R · 검색 ⌘F ·
    프로젝트 보조 패널 ⌘⌥I(P3·P4에서)
  - 3컬럼: 사이드바 | 목록 | 상세. P4 자료 열람에서 목록 컬럼을 접을 수 있습니다
  - 오류 Alert은 지금 보고 있는 창에 뜹니다

### 3.1 공지 레인

- **N1 공지 목록** — 화면(목록) · 전체 · 1
  - [작성] 버튼 — 운영진 모드 · 3
- **N2 공지 본문** — 화면(상세) · 전체 · 1
  - 읽음 처리
- **N3 읽음 통계** — 화면(상세의 탭) · 운영진 모드 · 3
  - 표(정렬 · 다중 선택)
- **N4 공지 작성** — 미정 · 운영진 모드 · 3
  - 작성, 대상 지정

### 3.2 스레드 레인

- **T1 스레드 목록** — 화면(목록) · 전체 · 2
- **T2 스레드 방** — 화면(상세) · 전체 · 2
  - 대화 · 나가기 · 신고
  - 초대 · 강퇴 — 방 역할 `OWNER`·`ADMIN`
  - 역할 변경 — 방 역할 `OWNER`
  - 강퇴되면 방을 닫습니다
- **T3 스레드 방 창** — 창 · 전체 · 2
  - T2와 내용이 같습니다. 여러 개를 동시에 띄울 수 있습니다

### 3.3 프로젝트 레인

P 레인은 계정별 개인 로컬 작업 공간이며 모두 단계 2.5입니다. UMC 로그인과 전체 점검 정책은
G2·G3을 따릅니다. 개인 로컬은 팀 공유 계약 없이 저장한다는 뜻이며 비로그인 진입을 뜻하지 않습니다.
PM·디자인·개발은 관점 배지로 표시하고 권한 배지와 구분합니다.

- **P1 프로젝트 목록/시작** — 화면 · 전체
  - 개인 프로젝트 이름 입력·생성, 기존 프로젝트 선택, 로컬 삭제 확인
  - **P1-빈 목록** — 상태 변형. `[프로젝트 만들기]`
- **P2 프로젝트 홈** — 화면 · 전체
  - PM·디자인·개발 관점 선택, 기능 목록, 최근 작업, 미결정
  - **P2-빈 기능** — 상태 변형. `[기능 추가]`
- **P3 기능 상세** — 화면 · 전체
  - 목적·완료 조건, 연결 자료, 수동 준비 항목, 질문·개인 결정 기록
  - 미결정/해결 상태와 원문 위치. 팀에 전달됐다는 표시는 없음
  - **P3-자료 없음** — 상태 변형. `[자료 연결]`
  - **P3-저장 실패** — 상태 변형. 입력 보존·다시 저장
- **P4 자료 열람** — 화면 · 전체
  - GitHub·Figma·Notion 원문, `[원문 열기]`, `[기능으로 돌아가기]`
  - **P4-로그인 필요** · **P4-권한 없음** · **P4-열람 실패** — 상태 변형
  - 붙여넣은 발췌와 출처·저장 시각. 링크만으로 본문을 확보했다고 표시하지 않음
- **P5 AI 작업 설명 초안** — 화면 · 전체
  - 목적·완료 조건·발췌·결정·미결정 선택, 모델 없는 초안 구성, 편집·복사
  - **P5-입력 부족** — 상태 변형. 본문 붙여넣기 또는 직접 작성
  - **P5-복사 완료** — 상태 변형. 복사 확인, 외부 전송 완료로 표시하지 않음
- **P6 기능·자료 연결 편집** — 시트 · 전체
  - 기능 이름·목적·완료 조건, 자료 제목·서비스·HTTPS URL·선택 발췌
  - **P6-검증 오류** · **P6-저장 실패** — 상태 변형. 입력 보존

팀 공유·담당자 전달·매칭 연결·AI 자동 점검은 후속이며 이 레인의 1차 화살표로 그리지 않습니다.

### 3.4 매칭 레인

- **M1 매칭 목록** — 화면(목록) · 전체 · 4
  - 차수 확인
  - [프로젝트 생성] — 조직 레벨·파트(Plan 파트)
  - [차수 개설] — 조직 레벨·파트(지부장 이상)
- **M2 매칭 상세** — 화면(상세) · 전체 · 4
  - 프로젝트마다 서버 권한에 따라 아래 셋 중 하나가 됩니다
- **M2-심사 심사 화면** — 상태 변형 · 프로젝트 권한(`application.canDecide`) · 4
  - 지원서 표 · 합격/불합격 판정 · 반려 확인 다이얼로그
- **M2-지원 지원 폼** — 상태 변형 · 프로젝트 권한(`application.canCreate`) · 4
- **M2-읽기 읽기 전용 상세** — 상태 변형 · 전체 · 4
  - 소개와 지원 상태·공개된 결과 확인
- **M3 프로젝트 생성과 공고·지원 폼 관리** — 화면 · 프로젝트 권한 · 4
  - 초안 생성 → 기본 정보 → 파트별 정원 → 제출 → 공개. 세부 권한은 서버 계약을 따름
- **M4 팀 확정과 결과 공개** — 화면 · 프로젝트 권한 · 4
  - 판정 검토·확정·결과 공개. 작업 공간 공유나 자동 생성으로 연결하지 않음
  - 위 두 권한이 모두 없을 때

### 3.5 문의 레인

- **Q1 문의 목록** — 화면(목록) · 전체 · 6
  - 챌린저: 본인 문의만. 비어 있으면 [문의하기]만 보입니다
  - 운영진: 표. 상태 · 대상 · 카테고리 필터, 안 읽음 배지
- **Q2 문의 상세** — 화면(상세) · 전체 · 6
  - 메시지 타임라인 · 입력창 · [종료]
  - 상태 표시: 접수 · 진행 중 · 종료
  - 메시지 편집·삭제 없음. 종료된 문의에 새 메시지가 오면 자동 재오픈
- **Q3 문의 등록** — 미정 · 전체 · 6
  - 카테고리 · 내용 · 첨부. 제목 칸이 없습니다

### 3.6 앱 밖

- **X1 시스템 인증 창** — 앱 밖. 카카오 로그인
- **X2 기본 브라우저** — 앱 밖. 자료 열람의 외부 주소, 업데이트 다운로드 링크

저장된 개인 프로젝트는 보존하고 같은 계정 재로그인 후 복원합니다.

## 5. 그리지 않을 것

- 리크루팅, 원격 푸시, 공지 AI 초안, 스레드 자동 분류
- 프로젝트 팀 공유·초대·담당자 전달·다중 기기 동기화·매칭 자동 연결
- AI 자동 누락 점검·변경 감시·토큰 대시보드·회고 생성
- 독립 칸반, 원문 문서 편집기, 외부 서비스 양방향 동기화
- 문의 메시지 편집·삭제, 챌린저 문의 목록의 안 읽음 배지, 수동 재오픈 버튼
- 역할에 따라 바뀌는 전역 사이드바

## 6. 미정

설계에 위치나 표시 방식이 적혀 있지 않은 것입니다. 추측해서 채우지 않고
미정 노드(점선 + `미정` 태그)로 그립니다.

| 대상 | 비어 있는 것 |
|---|---|
| 로그아웃 · 계정 · 설정 | 메인 창 어디에 두는지 |
| N4 공지 작성 · Q3 문의 등록 · M1 차수 개설 | 시트인지, 새 창인지, 상세 컬럼인지 |
| M1 매칭 목록 | 차수와 프로젝트를 한 목록에 두는지, 단계로 나누는지 |
| 프로젝트 보조 패널 | 자료·확인 사항의 폭과 접힘, P5 상세 전환 모양 |
| 외부 자료 인증 | 서비스별 지원 경로는 실제 앱 검증 후 확정 |
