## 2026-11-28 작업 반영

출석·스터디·구성원 하위 탭에서 같은 위치의 도구 버튼을 사용한다. 표시할 명령은 선택된 그룹과 권한을 따르고, 구성원 검색은 검색어를 지운 뒤에도 입력 포커스를 유지한다. [탭별 패널 가이드](../Codex/tool-panels.md)

## 창 탐색과 메뉴 막대

9월 시안은 창 툴바에 뒤로·앞으로·사이드바를 두고 바로 아래에 하위 탭 세 개를 고정했다. 챌린저는 ‘출석 체크 / 스터디·활동 / 구성원’, 운영진은 ‘출석 관리 / 스터디 관리 / 멤버 관리’를 본다. 선택한 탭을 강조하고 보조 패널을 열어도 탭이 가려지지 않게 했다. 탭 추가(+)와 닫기는 두지 않았다. 이 정리는 Light/Dark 합계 38개 프레임에 적용했고, 스터디·구성원 계열 8개 프레임에서는 하위 탭과 중복되는 제목·부제를 제거했다. [전체](https://www.figma.com/design/kM8a1siXgusAVRRgyUZ15U/?node-id=291-884) · [보조 패널](https://www.figma.com/design/kM8a1siXgusAVRRgyUZ15U/?node-id=291-1367)

현행 앱은 기본 세 탭에 조회 권한이 확인된 경우 ‘출석 관리’를 추가한다. 그룹 편집과 멤버 배정은 스터디 안에서 연다. 좁은 창에서는 분할 선택기가 메뉴로 바뀐다. 화면 상단 ‘일정 만들기’의 +는 생성 권한이 있는 사용자가 일정을 작성하는 동작이다. macOS **메뉴 막대**는 창 밖에서 현재 출석 가능한 참여 일정 최대 세 개와 ‘활동 열기’를 제공하며, 누르면 앱의 활동 화면으로 이동한다. [화면·메뉴 막대 구현](../../UMCDesk/Features/Activity/Presentation/Sources/ActivityPresentation.swift) · [메뉴 막대 시안](https://www.figma.com/design/kM8a1siXgusAVRRgyUZ15U/?node-id=291-2345)

## 운영진의 일정 생성과 요청 검토

9월 시안에서 상단 출석 도구는 현재 업무를 유지한 채 펼치는 패널이었다. 초기 화면의 진입 버튼과 펼친 패널 안의 실행 동작을 구분한다. ‘출석 일정 만들기’ 진입은 상단 출석 도구 안에 두고, 운영자 패널에는 일정의 운영 기준·행사장 지도·요청 검토를 배치했다. 운영자가 보는 지도는 행사 장소와 인정 범위를 설명하며 챌린저 개인 위치를 대신 표시하는 용도가 아니다. 위치 확인·일정 작성 폼은 입력 영역과 하단 버튼의 기준선을 맞추고, 일정 작성에서 기본 정보·출석 시간·참여자를 순서대로 확인하도록 했다. [일정 만들기](https://www.figma.com/design/kM8a1siXgusAVRRgyUZ15U/?node-id=368-1536) · [운영 도구](https://www.figma.com/design/kM8a1siXgusAVRRgyUZ15U/?node-id=406-2564)

현재 생성 권한이 확인되면 활동 헤더에서 작성 시트를 연다. 기본 정보·일정 시간·진행 방식과 장소를 입력하고, 출석 추적 권한이 있으면 출석 인정 시간을 설정할 수 있다. 대면 일정은 장소명과 지도 좌표가 필요하다. 출석 추적 시 참여자와 시간 순서를 검증하며, 오류를 고친 뒤 같은 폼에서 저장한다. [ScheduleEditor](../../UMCDesk/Features/Activity/Presentation/Sources/ScheduleEditor.swift)

9월 출석 관리에는 대기·전체 현황을 오가는 화면, 필터, 사유와 접수 정보, 선택한 요청 승인·거절이 있었다. 현재는 출석 명단 조회 권한(`ATTENDANCE.READ`)으로 관리 탭에 진입한다. 일정별 승인 권한(`APPROVE`)과 대상자의 대기 상태를 확인한 뒤 개별 판정을 확인 대화상자에서 확정한다. 조회 권한 회수 시 명단과 열린 판정 확인을 지우고 출석 체크로 돌아간다. 전체 통계·일괄 판정 화면은 9월 시안을 근거로 구현됐다고 판단하지 않는다. [출석 관리 시안](https://www.figma.com/design/kM8a1siXgusAVRRgyUZ15U/?node-id=291-1931) · [권한 조회](../../UMCDesk/Features/Activity/Data/Sources/StudyOperations.swift) · [판정 및 권한 회수 테스트](../../UMCDesk/Features/Activity/Presentation/Tests/ReviewAccessTests.swift)

## 다음 변경을 기록하는 방법

활동의 동작·권한 정책·시안이 바뀌면 해당 PR에서 이 문서의 업무별 행을 갱신한다. 시점, 누가 어떤 화면에서 무엇을 하는지, 바꾼 이유와 코드·PR·디자인 근거를 적는다. 과거 결정을 보존하고 새 기준 커밋과 시안 노드를 명시한다.

검수할 때는 변경된 역할과 경로를 Light/Dark에서 따라간다. 좁은 창과 큰 글자에서 선택한 탭·상태 문구·주 행동을 찾을 수 있는지, 키보드와 VoiceOver로 일정·대상·판정 상태를 구분할 수 있는지 확인한다. 데이터 변경이 있다면 권한 회수, 빈 결과, 요청 실패·재시도, 중복 제출을 해당 업무에서 확인한다. 검수한 코드·테스트·화면과 확인이 남은 조건을 PR에 기록한다.
